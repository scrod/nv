# Separate WAL durability from provider work

NV will keep ordinary WAL append/synchronization on a serial durability lane separate from the serial provider lane used for coordinated scans, materialization, note-file mutations, checkpoints, and journal namespace changes. Journal activation exclusively creates and synchronizes the header and current-host claim on the provider lane before handing the root-session-lifetime open descriptor to the durability lane. Provider work may block for network access, but it must not block the UI or delay later local journal durability.

`JournalLaneIndependence` checks the headline progress obligation with no fairness on provider work: after provider completion is permanently disabled, weakly fair local append and barrier-sync actions must still make every admitted edit durable. This focused model is separate from `JournalLifecycle` so a provider-stall dimension does not multiply its registry, root, and recovery scenarios.

Each opened directory has one root session incarnation that owns its rooted-directory reference, provider lane, presenter, cancellation state, and independent note/artifact dirty generations. Detached note-reconciliation transactions take an exact provider fence over the authoritative-note catalog projection and all-candidate persistent-version-identifier set, validate note-content and structural generations, and may commit only while that same root session incarnation remains active. Artifact status/recovery cannot complete or delay the note generation. Late completions from a replaced or closing incarnation are discarded without a separate global generation counter.

A verified move of the same directory under unchanged provider authority retains the root session and structural generation because the rooted descriptor, operation-local references, and validated File Provider APIs remain attached to the same items. A provider authority/account change instead fences the old incarnation and creates a provisional successor. The replacement transfers the continuously held rooted descriptor, directory lock, active journal, and pending local obligations rather than introducing another journal or an authority-generation counter. It drains and removes the old presenter and observers without closing that descriptor, registers successor-owned observation, and revalidates namespace and journal identity. The provisional successor owns local durability but cannot publish provider-derived results; successful revalidation atomically makes it the fresh active incarnation, while ambiguity leaves it provisional and retryable. The existing session check therefore rejects both old callbacks and provisional results completed before promotion. This transient state requires no persistent handoff record or second scheduler.

Provider-authority uncertainty and local journal durability are independent. Authority lookup or account continuity may remain unknown while editing continues against the same rooted directory and healthy journal descriptor; only provider-derived publication and cleanup stay frozen. Vnode deletion or revoke, deletion accommodation, or append/outbox-drain/barrier failure instead suspends edit admission, urgently drains every already admitted record through the existing durability lane, and retains each pending obligation until `NVBarrierSyncFileDescriptor` succeeds. Editing resumes only after rooted identity, namespace recoverability, and the active descriptor/header/claim are revalidated and the barrier completes. A permanently revoked or unlinked descriptor cannot resume that session; the in-memory store remains available for **Save Current Collection As…** or explicit abandonment. This adds no second scheduler or durable state.

Suspension and lifecycle quiescing reuse one authoritative `NotationController` mutation-admission check with independent reason bits. `NVRootSession` owns only the durability reason; `AppController` owns the lifecycle reason. Either blocks mutation, clearing either cannot clear the other, and their UI/retry state remains separate.

The root session also monitors its existing directory descriptor for vnode delete, rename, and revoke events. Rename enters the same identity/authority verification above; revoke and every unsupported or ambiguous result leave continuity inconclusive. Delete proves that the opened vnode was unlinked. It cancels the old incarnation only when ordinary-local authority or corroborating provider identity also proves that no equivalent logical root remains; provider eviction or same-item vnode replacement remains inconclusive. Confirmed loss forbids further publication into that root, does not attempt a normal old-root checkpoint, and does not infer that NV owns the last system file descriptor. The user may reopen a different-identity replacement as a fresh root, or save the frozen live collection into an exclusively created destination through the existing checkpoint and storage-export machinery. Reopening closes the old session before fresh startup; saving keeps its canceled session, open journal, and host-local claim as untouched evidence until the unattached destination checkpoint is accepted. NV adds no cross-root reconciliation, journal transplant, escrow format, or claim-transfer protocol.

For provider-managed roots, corroboration is one reverse-identity lookup: use the captured domain/item pair to obtain the exact domain manager and ask for the user-visible URL of that item. A validated same-pair URL proves survival; only an exact `NSFileProviderErrorNoSuchItem` for that captured item after a vnode delete proves loss. Every missing domain, unavailable/unsupported manager, mismatched URL, provider/account/network error, or other ambiguous result retains Retry. The complete recipe remains disabled until AV-08 validates it from the supported consumer-app context.

Normative requirements: `AUTH-01`, `DUR-01`, `ROOT-01`, `WAIT-01`.
