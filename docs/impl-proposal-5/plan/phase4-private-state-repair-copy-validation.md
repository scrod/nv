# Phase 4C–4E: private state, repair and copy qualification

Date: 2026-10-05. Scope: the portable library's controlled local storage paths.
The [implementation plan](phase4-private-state-repair-copy-plan.md) supplies the
scenario IDs. The specification, ADR-0016, Protocol and LocalStore remain the
policy authorities. Provider evidence, file installation, credential provisioning
and application surfaces belong to their later adapter gates.

## Implemented production boundaries

### Private records and pending ownership

`PrivateRecordsV1.swift` implements bounded canonical settings, association,
pending snapshot and reservation encodings. The
[record contract](private-record-contract.md) inventories legacy settings and
freezes layouts; independent Python-generated bytes and Swift decoding tests
check field participation, bounds, unsupported versions and malformed neighbors.
Both profiles keep these records in encrypted private database pages.

Settings and association consumers check the live store/session and expected
group generation. Five dedicated pending roles—immutable payloads, current item
references, reservations, settlements and their indexes—share the existing
SQLite transaction boundary. A failed latest replacement preserves the old
reference and bytes. Latest B and admitted frozen A have independent owners.
Settlement removes only the matching latest reference; optional cleanup can leave
extra unreferenced bytes after a crash.

Preparation reserves exact operation/action/nonce inputs. Re-review of an
uncommitted observation keeps its reserved birth and advances the item generation,
fencing the previous capture. Complete accepted membership, including its causal
closure, recovers an Import whose callback was lost even after its birth is
deleted. A persisted reservation supplies retry identity; fresh review remains
necessary for an uncommitted manual choice.

The settlement consumer checks the pending generation **before** invoking the
controlled physical observer and again inside the final reference transaction.
Neutral association requires current rows through the actual accepted prefix and
matching complete Current/value digests. An accepted Delete whose materialization
has failed therefore cannot expose an older editable cell as settlement evidence.
The neutral path records an observation without authoring an echo Put.

Actor-owned preparation is reserved before suspension. Quiesce drains it, and
preserved repair refuses to close its owner until preparation settles. The
headless observation callback qualifies storage applicability; real file/root
checking and atomic file installation remain Phase 6.

### Actual diagnosis and fixed-cut backup

`openDiagnosing` uses actual namespace, keyed opening, header/private validation,
required-history checking and derived reconstruction boundaries. Its immutable
result distinguishes access/entry-kind problems, credential or context mismatch,
unsupported/invalid required state and isolated pending failure. Raw NOTADB alone
leaves credential-versus-damage uncertainty explicit. Damaged derived rows follow
the established rebuild path while private inputs/settings retain ownership.

Backup owns a secondary keyed connection and fixed SQLite read transaction. It
captures H, private groups, required pin and current rows, plus a transient
streamed SHA-256 fingerprint of the complete pending tables. Bounded
`sqlite3_backup_step` turns allow continuing source writes. The reader and borrowed
directory handle settle on success, cancellation or failure. A separately owned
keyed connection compares the copied H, groups, pin, raw current rows/view metadata
and pending fingerprint **before ordinary recovery**. Normal fresh open can then
rebuild those derived rows or process already-captured ready work. Full exceptional
history/current/private auditing checks the resulting state before issuing
`CompletePrivateBackup`. Its `through` names the source read cut; normal recovery
may advance the copied store's own acceptance prefix. The pending fingerprint and
captured view metadata add no persistent table or long-lived cache.

Backup installs the existing exact `unlock/<descriptor-hash>.nvkey` wrapper and
checks it through normal unlocking. Public-profile recovery derives the specified
nonsecret database key without Keychain. Encrypted recovery uses the retained
same-key descriptor and supplied secret.

### Complementary repair and selection

Repair closes the owned source's connections and preserves its main database and
available journals. Salvage operates on a working copy. Independent components
use fresh keyed connections after errors, preserving independently readable
committed membership, immutable objects, private records and receive scheduling.
`PrivateSalvageOutcome.partial` reports incomplete components and the preserved
working location; only complete required private evidence supplies
`PrivateRepairEvidence` for complete reconstruction.

The candidate unions **committed provenance separately from validated bytes**.
Every known required object must have valid complementary bytes. Repackaged
occurrences retain their exact objects without repeating logical actions. Parked,
rejected and valid orphan bytes retain their classes; valid orphan contents alone
cannot turn into user actions. Complemented prerequisites wake their durable
dependents. Outstanding verification scopes are covered through exact source
membership, rather than copying a source-local H into a different candidate order.

Private installation preserves coherent settings, latest/frozen payloads,
reservations and settlements. Contradictory fragments produce an incomplete
outcome. Source-store bindings remain historical inputs under explicit repair
markers; the replacement receives its new store/association binding. Complete
history/current/continuation/private checks and normal fresh reopening precede
`VerifiedReplacement` issuance.

`SelectedStoreOwner` owns a real parent-directory lock. Activation consumes
restricted replacement evidence, checks candidate ownership/H, the expected
selected-record generation and fresh source database/journal observations, then
installs and reads back the existing 90-byte record with synchronization barriers.
macOS uses Foundation's replacement-directory/keep-backup route; Linux uses
exchange replacement retaining the displaced entry. An uncertain installed result
preserves both stores and requires readback. Source evidence and foreign occupants
remain preserved. Cleanup is a later maintenance decision.

### Repository copy and fresh-current export

`RepositoryCopy.preserveAvailable` copies captured available bytes without opening
a private database or unlocking ciphertext. Rooted no-follow handles, before/after
observations, streaming hashes, destination readback and metadata copying preserve
unknown associated files and report changed/unreadable entries individually.
Completeness of the captured inventory and known byte requirements is separate
from undisclosed remote history.

`copyRepositoryAndSavedWork` drains owned admitted commits, includes accepted
unpublished objects and exact descriptors, and reports excluded private pending
items. It uses the existing repository grammar:

- `NV Data/v1/keys/<descriptor-hash>.nvkey`;
- `NV Data/v1/segments/<writer-epoch>/<20-digit-sequence>-<segment-hash>.nvseg`.

Current-value export creates a fresh collection/key/bootstrap/birth set, validates
and reopens it, and preserves the supplied complete current values. Its fresh
history promise is distinct from repository-history preservation. Copy/export
results carry no selection authority: optional switching uses the separate
verified activation boundary.

## Language and independent evidence

Core decoding yields bounded immutable claims. Runtime permission/state types
have issuer-confined constructors: settings/association state, `PendingItemState`,
`PreparedPendingAction`, complete backup, complete/partial salvage, verified
replacement, selected state and copy/export results. Sibling clients also cannot
construct private pending-admission, activation-input or captured-history evidence.
The new private-boundary driver checks 29 ordinary/same-module cases, including a
valid production companion and health-report-versus-replacement rejection.
Existing runtime probes retain their actor/isolation/ownership checks.

Connections and lifecycle state stay actor-owned on blocking I/O executors;
transactions remain synchronous. New C buffers/handles have narrow owners and
bounded synchronous borrows. Core/Runtime retain strict memory safety, checked
concurrency and warnings-as-errors. Strict C warning diagnostics and instrumented
SQLCipher ASan cover the new physical boundaries; TSan covers contested cleanup
and ownership paths.

Four targeted runtime mutations reach their intended assertions: stale neutral
accepted-prefix coverage, fresh-birth allocation on re-review, dropped frozen
reservation during repair, and omitted unpublished history during active copy.
The common driver preserves intended discovery checks, independent canonical
fixtures, schema equality, old process campaigns and construction probes.

had retained a valid ready object at cut H; normal destination open accepted it,

also unnecessarily rejected before copying. Both tests failed against the original
implementation, with the independent expected values retained. The correction
checks exact copied state before normal recovery, then separately audits the
validated recovery result. Source work arriving after the cut remains excluded;
no safety assertion is relaxed. Five final backup functions pass under ASan

has its separate integrity case through the actual health/open consumer.

and fresh-process recovery, which these finite abstractions do not implement.

### Qualification limits

- Process termination, VFS write/sync failures and later encrypted-page corruption
  are distinct tested fault classes. Physical power loss is unqualified.
- Real provider placeholders, remote discovery, root repair and Apple credential
  effects remain adapter qualification, as do application UI/consent and actual
  external-file installation. This increment keeps their adopted policies intact.
- Repair deliberately refuses complete activation when a required private scan
  or known committed bytes cannot be supplied. Partial salvage preserves readable
  evidence; it cannot reconstruct an erased obligation it never observed.
- Cooperative directory/selection exclusion and fresh observations qualify the
  controlled local paths. Foundation replacement is not promoted to a universal
  filesystem compare-and-swap against uncooperative writers.
- Repair/backup complete audits may read required history. Healthy returning open
  keeps indexed current rows and required work; the pending fingerprint adds no
  startup history replay. Exceptional union/copy memory still scales with its
  captured history and is a later realistic-resource measurement target.
- Sources/failed candidates remain preserved. Automatic cleanup, 4F current-row
  zstd/physical-locality qualification and scheduled VACUUM are separate work.

The real page-damage fixture uses SQLCipher's `cipher_page_size`, then checkpoints
the source before flipping a main-database page. An earlier ordinary page-size
assumption and clean WAL page masked that damage; correcting the fixture made the
intended damaged-object path observable without weakening recovery assertions.
