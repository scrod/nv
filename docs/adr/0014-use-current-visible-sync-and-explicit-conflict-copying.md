# Use current-visible sync and explicit embedded conflict disposition

Status: accepted.

Routine provider reconciliation uses only a complete coordinated current-visible snapshot: two equal shallow note catalogs surrounding reads of selected current files, with unchanged root-session, structural-generation, and note UUID/LSN inputs. NV does not enumerate `other`, `unresolved`, or nonlocal `NSFileVersion` history to establish routine completeness or persist provider-version ancestry. The existing current-file compare-and-swap, merge, rename, deletion, and conflict-note rules continue to protect visible external work.

Routine conflict-note creation uses fresh ordinary version-4 identities. A modified, retired, or inconsistent deterministic recovery candidate does not suppress required routine preservation, including a still-local changed state racing current-file deletion. Automatic deterministic-candidate reuse/suppression belongs only to checkpoint-current reconciliation and base-mismatched WAL salvage; explicit unresolved-version recovery retains its separate slot policy.

Filesystem identifiers are optional association witnesses, not note identity. A nonzero document ID is accepted only with an equal volume UUID and a nonzero file ID only within one active root session; either must be unique on both association sides. Generation count is revision metadata. NV assumes no identifier survives provider eviction, rematerialization, replacement, or restart, and falls back to unambiguous filename/content matching and conservative import. Separate files carry no NV UUID xattr or sidecar; an unmatched file always receives a fresh random version-4 UUID.

Intentional deletion creates a UUID/LSN `DeletedNoteObject` only as pending and host-local-WAL evidence, independently of and without consulting legacy sync-service metadata. A verified complete checkpoint represents ordinary deletion by omission and carries no permanent general tombstone. Only the user's original coordinated expected-snapshot operation may remove the represented file; any mismatch or later same-name/same-body file is preserved/imported under a fresh UUID. RFC 9562 version-8 note UUIDs are reserved for the explicit-recovery and automatic-preservation algorithms. When such a note is deleted, its UUID also enters the checkpoint's compact monotonic retired deterministic conflict identity set, preventing later deterministic recreation without retaining every ordinary deletion.

This deliberately favors preserving possible work over remembering every deletion forever. After ordinary deletion coverage, a later note record that is not a deletion relative to the exact common base remains input, and an unmatched visible file is imported under a fresh UUID. Only deterministic conflict-note retirement persists indefinitely: insertion is idempotent and costs 16 payload bytes per distinct UUID before archive overhead, with no initial garbage-collection protocol.

One narrow current-checkpoint exception applies during root closure. If the exact expected-current checkpoint compare-and-swap returns `NVCheckpointInstallCurrentChanged`, replacement performs no write and supplies an exact coordinated snapshot of the canonical current `Notes & Settings`. NV compares its complete note set with the exact retained accepted checkpoint and complete live note set. A UUID present in the base and absent from a complete branch is that branch's deletion; no other absence implies deletion. NV first unions retired deterministic identities, then uses that effective set when allocating automatic conflict identities. Delete/edit races leave the source UUID absent and preserve the edit through the deterministic automatic-conflict identity. NV makes every newly published note/removal result and the entire merged retired set WAL-durable, settles ordinary separate-file obligations, and retries once against that exact current checkpoint. Each retirement uses the existing version-8 `DeletedNoteObject` form; base-mismatch recovery later projects only its additive retirement meaning. Reasserting the whole set protects identities formerly durable only in either superseded checkpoint branch. The competing checkpoint's preferences and other database-level metadata are ignored. Another current change, unreadable bytes, or failed publication returns to the ordinary retry/override UI without overwriting the checkpoint.

When Apple reports unresolved versions for a currently visible note file, NV shows an alert badge rather than automatically replacing the editor. Clicking the badge swaps a nonmodal read-only `ConflictResolverView` into the editor split-view subview in place of `LinkingEditor`. Its **Conflicts** popup contains **Current** plus an operation-local snapshot of only the unresolved versions Apple discloses. **Current** previews a frozen copy of the authoritative in-memory body, including admitted unsaved edits. Selecting another item asynchronously coordinates and reads that version's own URL using the source note's separate-file format captured with the operation, not a format inferred from the provider's version URL. Preview never mutates the note or substitutes current-file bytes.

`LinkingEditor`, its text storage, undo manager, selection, and scroll position remain allocated while the resolver sibling is visible. The resolver owns a separate noneditable `NSTextView`, or another text-presentation control with equivalent fidelity, scrolling, selection, copy, and accessibility behavior; it never shares or overrides `LinkingEditor` storage, delegates, undo, or persistence machinery. Per-member preview/wait/error state lives in a transient resolver model keyed by the captured member; popup/menu objects render that state but do not own the operation.

**Use this version** first revalidates the captured note UUID/LSN, structural generation, and root-session incarnation, then sends only the previewed body through the original note's ordinary mutation and save path, preserving its UUID, filename, title, labels, and database metadata. A mismatch applies nothing and refreshes the resolver; choosing **Current** makes no body change. After the chosen current-note generation is both host-local-WAL durable and exactly installed as its separate note file, NV coordinately revalidates that exact generation and marks every still-applicable member of the captured snapshot resolved. Versions arriving after the snapshot remain unresolved.

**Save as new note** is disabled for **Current**. Its stable recovery key contains a fixed versioned namespace, the source UUID, and the canonical recovered body only; title, labels, format/extension, filename, provider identity, and collision suffix do not participate. Candidate note UUIDs add a deterministic slot ordinal. NV reuses an exact live-body candidate, skips rather than overwrites a changed or retired candidate, and creates the lowest unused nonretired slot as an ordinary collision-adjusted `Title (conflict).ext` note using the captured title/labels. Only the selected provider member may be marked resolved, after that exact candidate generation is WAL-durable and locally installed and source/member applicability is coordinately revalidated. Deleting the ordinary note after confirmed resolution does not cause the member to be offered again.

After either action NV freshly queries `unresolvedConflictVersionsOfItemAtURL:`. The irreversible `resolved` setter has no error result, so this query is the sole success evidence. A failure before WAL durability retains no resolution authority; a failure before exact file installation retries the same generation; a failed/partial resolution rebuilds **Current** plus the returned remainder; and an ambiguous query retries only the query. Waiting and error state belongs to the affected transient member model, not the resolver view. The close **×** always restores `LinkingEditor` without canceling the current bounded background attempt, and ordinary editing resumes; stale source edits then prevent a pending **Use this version** from resolving. Exhaustion parks that item at **Retry when reopened**. Re-presenting the resolver from the badge automatically starts one fresh bounded pass for every parked item on that note without duplicating running work; there is no explicit Retry action. A fresh empty result clears the badge and restores `LinkingEditor` if necessary. No provider-version intent is persisted across launch. NV never removes a version, invokes `NSFileVersion` replacement, waits for upload, or persists a provider-version ledger. Resolved versions can remain in Apple history. The initial UI has no automatic or manual merge command; a later reviewed merge would require a trustworthy base and gains no broader resolution authority.

Noncanonical `Notes & Settings` versions are not recovery inputs; the checkpoint-current exception consumes only the exact canonical file that defeated the local CAS. NV provides no **Recover Notes**, automatic all-version recovery, automatic resolution, provider-version removal, or **Discard** path. **Rebuild from Note Files** uses only a stable current-visible file snapshot. This accepts that a historical branch Apple does not disclose as unresolved for a visible note is unavailable to NV.

Normative requirements: `DISC-01`, `PUB-01`, `REC-01`, `CKPT-01`, `WAIT-01`.
