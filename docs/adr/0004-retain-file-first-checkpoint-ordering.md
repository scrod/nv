# Retain file-first root-closing ordering

NV will freeze editing, complete a final provider/reconciliation barrier, and settle both WAL durability and affected separate-file writes before serializing and installing a root-closing database checkpoint. Quit and ordinary folder switching use the same closure path while the old root remains writable enough to complete it. Confirmed root loss cannot satisfy this ordering and instead preserves the old claim as interrupted-session evidence while the user reopens from disk or constructs an independent collection through **Save Current Collection As…**. Installation succeeds only after a coordinated read-back exactly matches the serialized bytes, decodes, and contains the expected checkpoint identity. A verified checkpoint either cleans its covered WALs after applicable qualification or demotes the closed active WAL to retained ownership; only a pre-checkpoint explicit override may preserve an active claim. A provably empty owned active WAL may be removed after directory durability without checkpoint upload qualification; if no checkpoint-scoped state or retained-backlog retry requires a new checkpoint, closure also skips checkpoint installation. Any uncertain bytes forbid the empty-WAL exception.

Every checkpoint transaction also enforces its expected-current bytes and available local-version identity as a local compare-and-swap immediately before replacement; creation and rebuild after authoritative absence require expected absence. A mismatch or unexpected appearance performs no namespace mutation and takes the caller's pre-checkpoint failure path; rebuild restarts discovery rather than adopting the appeared checkpoint. The precondition is never advisory and never silently adopts another Mac's checkpoint as merged settings. Remote state not yet delivered locally remains covered by exact fail-on-conflict upload when available and otherwise by conservative journal/version retention.

The same immutable receipt freezes both represented-journal coverage and every already eligible routine or **Recover Notes** provider-version identifier represented by the checkpoint. Provider-managed automatic cleanup waits for exact upload qualification of that receipt; individual separate-file upload confirmation is unnecessary because the uploaded complete checkpoint is the recovery backstop. This establishes local crash consistency and avoids serializing a second set of pending export obligations, but it does not promise provider cross-file delivery order: separate files remain the routine note-sync representation and any divergent database version remains recovery evidence.

`CrossMachineGenerationSafety` checks this ordering across two distinct edits and journal generations, including crashes at each modeled demotion/advance/removal boundary, rollback to an older synchronized retained-coverage identity, writer-machine loss after any installed checkpoint, reordered reader delivery, and later checkpoint-3 cleanup. It distinguishes physical loss of work that never reached another replica from failure of the distributed retention protocol. The model deliberately remains separate from the larger one-edit distributed glue model to avoid multiplying unrelated startup and preference states.

Normative requirements: `DUR-01`, `QUAL-01`, `CLEAN-01`, `CKPT-01`.
