# Use a controlled restart for storage-format changes

Changing the database passphrase, encryption, or first-class provider-managed storage format also changes the checkpoint/journal contract, so it cannot be an ordinary live preference mutation while one root-session-lifetime WAL remains necessary. NV freezes editing, settles current obligations, installs and verifies a complete old-format checkpoint, and retires the old journal only after its applicable durability barrier.

Keychain Services and checkpoint replacement are separate durability domains, so NV uses copy-on-write credential cutover rather than updating the accepted credential in place. It builds an isolated target `NotationPrefs` snapshot while leaving the accepted preferences and old Keychain item untouched. A remembered encrypted target receives a fresh `keychainDatabaseIdentifier` and add-only generic-password item; NV reads that item back and validates it against the target KDF/verifier before installing a checkpoint that references it. The verified target-checkpoint installation is the commit point. Only afterward does an orderly transition attempt best-effort old-item deletion and then restart to publish the target preferences. A crash before installation therefore preserves the old pair, while a crash after installation preserves the new pair and may retain inert old or unreferenced credential residue; neither case can strand the installed checkpoint. No cross-resource transaction or migration ledger is assumed.

For an ordinary encryption change, NV atomically installs the same complete store under the staged target encryption settings and restarts before accepting edits. When entering the first-class provider-managed storage contract, it instead exports every live note through the plaintext writer, verifies an unchanged provider catalog token across the export fence, installs the complete unencrypted checkpoint, and restarts with a fresh journal. NV extends the existing conversion confirmation flow with cleartext disclosure and, for RTF/HTML input, a new warning that formatting and attachments are discarded. A selected folder moved under provider management triggers the same blocking conversion. Until the final install, the complete old-contract checkpoint itself identifies an incomplete transition; retry reruns export idempotently and preserves divergent files, so no intermediate unreleased epoch-5 compatibility path is maintained.

**Save Current Collection As…** reuses that export machinery without becoming a live-root format mutation: the new directory is exclusively created and remains unattached and uneditable. It also reuses copy-on-write target-credential provisioning without reusing credential ownership. An encrypted remembered destination receives a fresh add-only, read-back-validated `keychainDatabaseIdentifier` before any checkpoint names it; unremembered or unencrypted targets clear the identifier. Save As never aliases, updates, or deletes the source collection's item, so a later same-collection cutover can delete only that destination's unique former credential. NV then installs a complete single-database bootstrap, decodes it into detached target state without mutating the frozen source controller, optionally exports separate files and installs the final target-format checkpoint, and opens the accepted destination with a fresh journal. A crash after the bootstrap leaves a complete ordinary collection, while an ambiguous bootstrap installation conservatively retains its newly provisioned item; this path needs neither a restart-only transition state nor a migration ledger.

Normative requirements: `START-01`, `DUR-01`, `CKPT-01`, `ROOT-01`.
