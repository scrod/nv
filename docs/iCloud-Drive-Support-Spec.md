# Robust iCloud Drive Support

Status: adopted design — immutable segment collections (implementation proposal 5). Production implementation and release verification remain incomplete.

This is the normative product and safety contract. [CONTEXT.md](../CONTEXT.md) defines vocabulary; the [ADRs](adr) explain current decisions, not their historical sequence. [Implementation proposal 5](impl-proposal-5/README.md) supplies the plan. Its [Protocol](impl-proposal-5/Protocol.md) and [Encryption](impl-proposal-5/Encryption.md) sections are the detailed algorithm/wire annexes; items explicitly awaiting vectors/review remain release gates. Proposal 4 and checkpoint/WAL-specific models are retired references, not authority for segment collections. Legacy opening/export remains separately supported.

## Authority and scope

For a plain-language map of the layers, graph relationships and durability terms used below, see the [protocol reading guide](impl-proposal-5/Protocol.md#reading-the-terminology). The [glossary](../CONTEXT.md) groups definitions by concept and links them to their written rules and bounded models. In particular, Current is an editable note value, not provider-current; local admission is not durability; and model publication is not provider publication.

- The live in-memory store is authoritative during use. Search remains synchronous in the same input/runloop cycle; provider access, encoding, crypto, reduction and disk barriers stay off-main. Admission changes live values immediately but is not crash-durability acknowledgment.
- Immutable dependency-linked NV operations carry committed identities, values, deletion intent and meaningful action history between Macs. Complete host-local segments supply recovery; exact copies in the selected provider folder supply transport. There is no second mutable WAL, shared mutable database, HEAD, membership/receipt registry or global sequence allocator.
- PlaintextFilesV1 contains interoperable plaintext note files plus visible NV Data/v1 history. Separate files remain editable inputs/outputs, not the sole transport or history authority. EncryptedSegmentsV1 contains encrypted history/key descriptors and no plaintext note files in the provider folder. It preserves supported rich content; plaintext export/external-editor access is explicit and outside that folder. A continuously maintained local plaintext mirror of encrypted notes is deferred.
- Both profiles use an ordinary user-selected directory. No dedicated iCloud container, CloudKit, custom File Provider extension, provider-brand switch or provider-private API is required. iCloud Drive is the tested first-class target; other providers use the same conservative contract with their documented validation limits.
- Indexed current-note rows and compact authoring context provide private startup state; no packed startup cache is supported. Required Local State owns settings, association and local observations in the same private SQLite database. Provider snapshot roots/pages remain separate immutable history objects with their own validation requirements. Segment collections create no Notes & Settings; epoch-4 compatibility applies only to legacy collections and explicit legacy exports.
- The provider may deliver objects/files independently, reordered, duplicated, evicted, delayed or not at all. Provider-current/upload status never proves all devices synchronized. Missing provider entries never retract accepted history; a new Mac cannot detect an undisclosed valid branch.
- Apple unresolved file versions remain a separate explicit-disposition source for visible plaintext files. NV's retained history supplies Note History, Recently Deleted and causal conflict handling without depending on Apple retaining/disclosing overwritten or deleted bodies.
- V1 retains all final accepted/sealed history and required descriptors locally and at the provider. Snapshots do not authorize pruning. Deleting a note or undoing an edit does not erase history. No automatic expiry, permanent-delete UI, device revocation, in-place GC or remote-erasure claim is included.

### Input and content scope

Consult Apple's text-editing API contracts, Human Interface Guidelines and ordinary macOS/NV behavior before specifying new input-processing policy. Preserve standard AppKit input-method behavior. NV's saving, remote-update and editor-attachment code must not interrupt composition unexpectedly, lose input, or treat internal text-storage notifications as independently completed user actions. Local focus changes, closing/switching editors and editing through another window use normal AppKit input-context handling, not an NV rule that always discards marked text. Prefer deferring application of a remote body change to the active editor until a safe input boundary, then revalidate and use the existing merge/conflict rules; composition alone is not a conflict or reason to prompt. Other notes and local durability continue. A separate committed-text snapshot or custom composition state machine is not prescribed; synthetic probe adapters are implementation candidates, not platform requirements. No additional durable draft-recovery protocol is adopted. See [platform contracts and integration checks](Apple-API-Contract-Validation.md#text-input-and-undo-platform-boundary).

File attachments are out of scope. Current format-design and generator work targets plaintext; further RTF/HTML codec, rendering and rich-content identity work is deferred pending a separate retain/remove decision. This does not remove epoch-4 opening/recovery/export or authorize silent flattening/data loss. Existing supported rich inputs still require preservation through their supported path or explicit unsupported/conversion handling before migration; no unfinished rich codec is a production format.

Principal ordering is admission → complete local segment/parent barrier → independent provider/projection work. Reception is exact local installation → dependency completion/validation → generation-fenced reduction. Neither path passes through a shared Notes & Settings transaction.

An owned receive interrupted by concurrent local saves resumes after those saves
settle, without requiring another provider event. Each attempt retains complete
validation and ownership checks; storage failures remain distinct from contention.
Definite rejection of retained incoming input atomically settles that candidate's
queue state while preserving its bytes and accepted history. After failure or
crash, the candidate is either durably rejected or retryable. Its dependents remain
retained and unaccepted, with rejected-prerequisite diagnostics distinct from
missing data and from a rejection of the dependents themselves. Unsupported
prerequisites may become usable under a future validator.

- Use Foundation's user-domain Application Support location, restrictive 0700 directories/0600 files where supported, rooted/non-following operations and exact ownership checks. Do not mark the private database purgeable or backup-excluded: it contains required history/state even though some rows are disposable. Back it up consistently with SQLite, not by copying only a live main file. [LocalStore](impl-proposal-5/LocalStore.md) defines the transaction, key lifecycle, backup/repair activation, current-row and fast-start contracts; production adapter qualification remains an implementation gate.
- NV Data is an ordinary visible directory, not a package, hidden alias or compatibility mirror. Reserve protocol/database names against note import/export. Preserve and report a foreign item, symlink or incompatible bootstrap there; never overwrite it to initialize a collection.
- Install immutable repository objects from their exact checked sealed bytes through a complete owned stage and native exclusive rename. Verify the installed object, synchronize its file and every affected nested directory, then recheck the rooted context before issuing installation evidence. An equal existing final still requires exact verification and those barriers. Unsupported exclusive installation is an explicit capability outcome; local saving retains its separate durability path. Preserve conflicting occupants, displaced stages and uncertain effects for exact-input retry. Installation evidence is distinct from private accepted-history evidence; the publication caller must establish both. [Physical contract and qualification](impl-proposal-5/plan/phase5/02-immutable-files-validation.md).
- Collection ID identifies logical history; local-store ID identifies one private copy; a fresh random writer epoch allocates immutable names for one editable session; operation IDs identify canonical changes; note births identify logical creations. A separately fresh action origin groups one editable collection session's authored actions and is stored in those records as causal provenance. None identifies a permanent physical file or authenticates a person/device. Restart/restored backups never resume an old writer allocator or native `NSUndoManager` continuation; sealed bytes retain their identities for retry.
- Operation hashing includes canonical parent IDs and full values, not the enclosing segment hash. External locators identify exact immutable objects; intra-segment references point backward. No hash cycle, cross-writer LSN order, maximum-sequence coverage or mutable head is permitted.
- Retain nonblocking exclusive directory-descriptor flock ownership for the root and private store before their respective recovery/mutation. Root contention or unsupported acquisition grants no provider writer. A recreated directory at an old path is another resource. No .nv-root.lock child or per-session WAL lock substitutes for the directory object.
- Fresh opening of a deep HFS+ root has an explicit compatibility limitation: supported Foundation APIs may fail to supply the positively bound file reference required for coordination when its pathname exceeds `PATH_MAX`. Report root access unavailable and preserve the repository and healthy private editing. Ordinary HFS+ access and an already-owned root's qualified deep-move behavior remain supported. Retry or explicit relocation/reassociation through the later root flow must establish physical authority anew; Save Current Collection As… remains available from a complete private closure. This limitation alone does not offer Work Offline, authorize a different root, or permit uncoordinated provider effects. Descriptor-relative addressing retains its existing long-path guarantees wherever the required Foundation seam is usable.
- The private database owner retains one actor-confined connection. Establish its fixed schema, header, collection/descriptor binding and configuration at opening, then compare callers against that checked connection context. Bracket each synchronous database turn with physical ownership checks and check immediately before and after transaction commit. Ownership failure blocks the affected operation; retry requires positive identity of the same held directory and database, or a fresh opening under the existing recovery rules. Mutable records, history health and asynchronous generations retain their operation-specific checks. Exceptional current-row reconstruction checks required private inputs both when capturing and when installing its result. An already-committed receipt remains historical evidence even after orderly close; consumers still check session/generation and physical authority before new effects. [Connection lifetime and qualification](impl-proposal-5/plan/phase5/private-connection-reuse.md).
- A returning offline session still requires exclusive positively associated private-store ownership. It may recover/edit locally while an unavailable provider root cannot be opened; root ownership is required before root access/publication resumes. Known live root-lock contention is not bypassed by Work Offline. Retain any already-held root lock continuously through move, authority handoff, canceled close and teardown. Never unlock borrowed/duplicated descriptors or let a scan/cancellation handler close the owner.
- Local State contains a non-derived retained-history pin: every required descriptor plus the maximal accepted segment locators whose dependency closure must remain locally available. Exact object retention, acceptance membership and pin advancement share one database transaction; stored-but-parked objects are not accepted history. A surviving pin positively identifying missing/corrupt evidence prevents editable success. Healthy startup reuses prior validated acceptance under local continuity rather than rereading every historical byte; on-demand detection enters repair. This is bounded private loss detection, not a synced HEAD, an undo cursor, proof against undetectable total rollback, or permission to prune ancestors.
- General snapshots v1 carry canonical exact **retention-parent** root locators in their paged manifest, protected by the snapshot's envelope/tree/count/digest checks. The single layout always contains eight category counts, including a zero retention-parent count when empty. Capture the accepted snapshot-root frontier together with the owned acceptance prefix. Accept a parent link only after checking that exact supported root's accepted membership, locator, kind, collection and sealed bytes; reuse its previously validated dependency closure. Root/pages, membership, parent edges, frontier advancement and wakeups commit atomically. Remove only the named parent tips; concurrent or later independent roots remain until explicitly covered. Missing/unsupported parents retain normal waiting/blocking outcomes. Initial bootstrap encodings remain unchanged.
- Retention ancestry preserves objects independently of a snapshot's represented logical operation cut. An older cut may cover a newer-cut root without electing the older values, superseding revisions or deleting bytes. All accepted ancestor bytes remain required; on-demand damage checks and durable verification obligations still apply. Fresh reconstruction shares checked logical history and deduplicates required page/envelope work within each traversal attempt. A sequential covering chain requires one startup root check; arbitrary concurrent width remains unbounded. [Format and acceptance contract](impl-proposal-5/plan/general-snapshot-record-contract.md), [qualification](impl-proposal-5/plan/phase-4-improvements/snapshot-retention-coverage-validation.md).
- Local State also indexes private pending-file snapshots and operation reservations. These snapshots are not segments, an external-save archive, disposable staging, or a source of note identity. They are never published to `NV Data`; the [pending-file protocol](impl-proposal-5/Protocol.md#pending-file-retention-and-retry-identity) defines their retention, crash recovery and release. Loss of an unadmitted snapshot is a distinct recovery-buffer loss, not proof of lost committed history.

## Local admission, sealing and recovery

- One main-thread predicate combines independent startup/locked, local durability/key/association and lifecycle reasons. It precedes every editor/programmatic/title/label/format/import/delete/undo mutation and undo registration. Provider waiting alone is not a reason. Preserve admitted text on later failure; urgently drain pending work and block subsequent mutations until healthy recovery.
- Reuse pending UUID/LSN generations and coalescing within an open saved-edit group. Capture immutable full values/action metadata without losing before-state, creation, deletion, retirement, restoration or completed named-action boundaries. Resolver, external-editor and lifecycle boundaries force asynchronous capture/barrier. Stale completion cannot clear newer work.
- Preserve NV's existing capture scheduling baseline: 2.7 seconds after the last edit, plus a 15-second timer from the first pending edit that subsequent typing does not reset. These are scheduling targets, not hard real-time or disk-durability promises. Keep synchronous search/input unchanged and encoding/I/O off-main; pending native groups do not indefinitely defer capture of completed input. Scheduling a capture is neither completing an input-method composition nor creating a new user action. Exact action boundaries and existing forced lifecycle/external-handoff barriers remain required.
- One sealer per collection encodes complete groups in bounded worker memory and optionally compresses/authenticates. All new storage compression uses zstd; zlib is confined to legacy epoch-4 database/WAL compatibility. Provider compression is one independent dictionary-free frame under the [bounded profile](impl-proposal-5/Encryption.md#compression-profile); private-row dictionaries remain local codec metadata. The qualified private database transaction durably retains exact bytes and their complete acceptance bookkeeping before acknowledgment. Equal existing bytes/operations are idempotent; contradictory bytes preserve evidence and fail. Ambiguous retry queries the same committed identity, never reseals different content under an old identity/nonce. Provider final-name/directory barriers remain separate.
- Every parent is durably local or earlier in the same atomically installed segment. A child with a RAM-only parent cannot be acknowledged, applied as received history, used for external handoff or physical removal. Incoming children may be stored while waiting; no valid-looking prefix of a damaged segment is applied.
- Note operations and their complete action record occupy one envelope. Oversized bulk work is split into disclosed independently undoable batches before admission, never an implicit cross-segment transaction. Pending keystrokes are not promised power-loss durability before capture.
- Recovery honors complete database commits regardless of callback/upload flags. Before editable publication, drain durable ready Changes and their discovered required prerequisites, then catch up the current materialization. Select required work independently of queue order. Independent optional snapshot roots/pages remain durably queued until a successful checked host publication reserves the existing receive owner and starts its background drain. Bootstrap, exceptional reconstruction, known required-history checks and unfinished verification requests remain startup requirements. Uncommitted transactions are not accepted history. Newly applicable inputs still require complete validation; corrupt/unsupported inputs or missing known accepted dependencies cannot become editable emptiness. Current-row loading cannot waive scope or represented-history binding.
- Before checking accepted evidence whose damage diagnosis could otherwise be lost, commit an exact host-private verification request. Keep it through final graph/reducer checks. Successful verification settles only that request; discovered damage immediately fences the live owner and atomically replaces the request with the damage marker when storage permits. Failed diagnosis or settlement leaves the request replayable. Returning open verifies unfinished captured scopes before editable publication. Cancellation and close retain unfinished obligations; replay verifies retained evidence rather than reissuing user commands. Admission is bounded, and persistent failures require an explicit recovery outcome rather than indefinite polling. Healthy stores with no unfinished requests retain indexed startup. [Concrete protocol](impl-proposal-5/plan/phase-4-improvements/durable-verification-recovery.md).
- Durable accepted/sealed objects and descriptors remain after clean quit, snapshots, upload, conflict resolution and Save As. Routine cleanup removes only exact owned disposable artifacts after use. Losing a machine before publication loses unpublished work unless a usable backup survives.

## Startup, creation and private current state

| Evidence | Outcome |
| --- | --- |
| Valid association/key and current materialization | Drain indexed startup-required Changes and prerequisites, catch up acceptance/materialization, and load all current note/search values and compact authoring context under the final publication fence. Independent optional snapshots run after successful publication; provider discovery is independent. |
| Invalid/unsupported derived current materialization, valid retained history | Reconstruct the materialization from validated retained history without resetting private settings/association. This exceptional path may require a full-history read. |
| Missing/corrupt private state or ambiguous association | Explicit association/settings recovery, never derived-view/collection-ID-based permission. |
| Complete returning history; no positively disclosed unread newer-provider object | Enable local editing after local health/ownership checks. Provider offline/full/unreachable is a sync-status condition, not a Work Offline prompt. |
| Complete returning history; provider positively discloses a newer version or required object whose bytes are not materialized/readable | Wait only for those named bytes; offer Work Offline to proceed from the complete local closure, or Save Current Collection As…. Preserve and reconcile the delayed evidence when it becomes readable. |
| Missing key or locked Keychain | Unlock/passphrase choices; private noneditable state, no secret deletion or empty fallback. |
| Fresh Mac, incomplete genesis/import/parents | Bounded asynchronous fetch, no partially editable collection. Complete authenticated snapshot may be previewed read-only while closure arrives. |
| Contradictory bootstrap/authentication/required codec or missing known accepted evidence | Preserve inputs and repair/retry/choose another collection; no guessed latest branch, downgrade or silent omission. |

- Snapshot preview requires all named bounded pages, counts/digests and complete displayed values. Editing additionally requires durable initial-import and stated history closure. Neither claims all remote heads arrived.
- Integrated startup keeps local admission, provider status and reassociation settlement separate. A missing returning association requires explicit binding. Reserve the selected attempt through the checked host callback; a throwing callback grants no editable publication or transport handoff. Root acquisition proceeds independently, and generic provider failure preserves a complete private startup view.
- A named startup wait may use the existing transport worker/timer for a bounded materialization attempt while ordinary provider publication remains held. Exact readable bytes, authenticated against the disclosed locator and retained through normal receive, settle that wait; download-request success alone does not. Work Offline releases the initial admission wait while preserving pending evidence. Successful host publication enables ordinary discovery/publication on that same driver. Exhausted named attempts remain visible and are not reset by save or hint notifications.
- When an already-entered provider accessor makes a fresh readability check busy, Work Offline may use the original exact named disclosure after freshly checking complete local health and the same live root/attempt. This enables local publication and editing while preserving pending evidence; it grants no provider-write permission. Root invalidation, a different attempt or failed local health still rejects the choice. Same-root Retry can renew the wait without discarding its existing worker: exact completion remains routed to that physical root; old-root completion cannot settle a new-root association.
- Successful local publication and provider-worker attachment can settle in either order. The later settlement must enable ordinary transport through the existing live-root permission checks; finite startup interference cannot require another incoming object or user action to resume it.
- Passive bookmarks supply a candidate rather than a guarantee of identity. Independently compare the acquired directory with the stored physical association and the resolved candidate. Ambiguous, unsupported or different resolution preserves private work and requires explicit Re-open. That operation records the new association durably, reconciles ambiguous completion by record readback, and retains both old and new resources until actual old-accessor return. Retry applies only to the continuously held same directory. Keep at most one unsettled association transition.
- Snapshot intake distinguishes retained assembly bytes from accepted causal history. Retaining exact bytes and waking reverse waits share a transaction; parking rechecks requirements and replaces that candidate's waits atomically. Usable pages remain assembly inputs until a complete root/page set is verified and accepted. A prerequisite's own rejection blocks dependents without rejecting them or discarding shared pages. Optional snapshot preparation and delayed results may end at close; owned writes settle and durable ready/wait state survives reopening. Snapshot acceptance alone does not install its values as Current.
- Deferred optional intake uses the existing bounded worker and save-settlement wakeups. Repeated successful publications coalesce through receive ownership; an existing receiver completes its owned drain. After finite interfering saves settle, validation resumes without another delivery, timer or restart. Close retains unfinished input/verification records. Persistent storage failure follows explicit retry/recovery paths, with complete validation still required before snapshot acceptance or recovery use.
- Returning launches do not materialize every plaintext file or wait for unknown remote objects. Complete current bodies and compact per-scope authoring frontiers enter memory before editing/search; history UI/candidate indexes may finish separately without replacing newer action ordering. Work Offline bypasses only a startup wait for already positively disclosed evidence not represented locally. Do not wait for provider discovery to decide whether to show it, prompt for an evicted copy of bytes retained locally, or revoke an active session's editability when new provider evidence arrives. Fast normal launch is a measured release requirement.
- Capture the complete current-note rows, compact ordinary-edit authoring context, scope/reducer version, view epoch and represented prefix in one consistent SQLite read transaction. Traverse in table order and decode directly into final unpublished note/context storage, without a whole-collection intermediate encoded buffer; rowids are neither logical identities nor UI ordering. Validate row codecs and construct all in-memory notes/search state before editing. Recheck owner/lifecycle generation, view epoch and accepted/materialized prefixes before publication. Deletions and body-equal context changes must be reflected atomically in current rows/context; stale worker output cannot become editable. There is no separate packed format, cache certificate, batch token, changed-birth delta log or cache publication transaction. Full algorithm: [LocalStore](impl-proposal-5/LocalStore.md#concrete-returning-launch-algorithm).
- A checked opening capture may be consumed once after final owner/history/view/context/presentation checks; later host publication retains its live-generation fence. If acceptance advances before current-row installation finishes, capture/publication must retry after materialization; that transient lag is neither missing required history nor permission to publish partial values. Private compression dictionaries are derived current-row metadata, bound by full digest and installed atomically with referencing rows. Missing/invalid named codec data requires complete materialization reconstruction from healthy retained history, preserving required private state. The [physical row contract](impl-proposal-5/plan/private-current-row-codec.md) changes neither history identities nor provider-envelope decoding.
- Before initial publication, several accepted general-reducer actions may be materialized together from one checked captured prefix. Every intermediate action participates in reduction. Install complete final rows/context atomically only while the exact starting view and accepted target still match; allocate a fresh view epoch and recapture after interference. Preserve acceptance, retained bytes/frontiers, required private state and pending work independently. Live-session materialization retains its separately qualified per-batch route.
- Local State independently persists association/bootstrap pin, retained-history pin, settings/UI state and generation-tagged file receipts. Sensitive fields are encrypted. Durable action origins, causal scope parents and compensation/redo relationships live in retained action records, not private state. Old receipts require fresh physical validation; none is surviving delete permission. Unavailable Keychain is not corruption; missing private state is not merely derived-row damage.
- The [equivalent SQLCipher current-note/search benchmark](impl-proposal-5/plan/remaining-storage-validation.md#startup-remove-the-packed-cache) supports removing the packed cache and its supporting machinery, not deferring it as a supported optional extension. Current materialization, durable ready-work recovery, compact authoring context and final publication fences remain required. The [aged clean-quit investigation](impl-proposal-5/plan/clean-quit-locality-strategy.md) identifies residual locality costs and non-rewriting candidates; it does not freeze a new format or prove packed-equivalent performance. Physical read-ahead advice cannot replace any of those logical checks or make otherwise valid startup depend on its presence.
- Optional full `VACUUM` may compact a healthy private database opportunistically while idle, based on both elapsed time and measured fragmentation, with adequate temporary-space/work budgets. It is not SQLite auto-vacuum mode, history pruning, damage repair or mandatory startup/quit work. Required persistence takes priority; automatic execution requires qualification of interruption/settling and subsequent durable-commit latency. Invalidate physical read-ahead hints before layout changes and retain worker/owner resources until settled. Failed/skipped maintenance alone cannot invalidate a durable save; genuine database damage follows ordinary recovery. Numeric thresholds and benefit lifetime remain qualification work under the [maintenance policy](impl-proposal-5/plan/clean-quit-locality-strategy.md#adopted-opportunistic-full-vacuum-policy).
- Creation is explicit for every preexisting selected directory. Only an exclusively created destination may initialize silently within that operation. Empty listings/ENOENT never prove remote absence. Concurrent unrelated bootstraps remain distinct and require selection.
- Capture complete initial values/count/canonical digest before genesis. Dependency-linked batches and ImportComplete must match that commitment; a final complete snapshot accelerates bootstrap. Descriptor→genesis and snapshot→completion references stay acyclic. Interrupted import is not successful empty/partial creation.
- Exceptional current-row reconstruction verifies the selected snapshot's represented logical operation ancestry and complete actions, then includes every accepted operation outside that cut through the captured local target. Earlier-arriving branches and extra complete groups in required envelopes remain included. Reuse unchanged snapshot cells and shared reducers for affected scopes, preserving exact revision/action, Delete, retirement, disposition and restoration context. Install complete rows/context atomically under a fresh epoch after owner/history/starting-view checks; preserve required private state and pending work. [Concrete mapping](impl-proposal-5/LocalStore.md#exceptional-bootstrap-and-snapshot-reconstruction).
- Rebuild from Note Files is explicit salvage to a fresh collection, not replacement of missing history. Use one stable current-visible snapshot; recognize txt, text, utf8, taskpaper, rtf, html, htm; unknown groups require a decoder or Ignore choice. Mixed inputs require a target codec/profile and detached conversion with formatting/attachment-loss disclosure. Preserve sources; verify the complete target before attaching. Encrypted targets need not flatten supported rich content.

## Repository and private-store damage and repair

NV classifies observable evidence, never presumed cause. Offline delivery, provider eviction, backup restoration, permissions changes, user deletion and filesystem damage may produce the same observation. For the selected root, `NV Data`, protocol subdirectories, the private Application Support hierarchy, Local State, descriptors and immutable objects, record: positive physical association, entry kind without following symlinks, readability/materialization, parent/final-name writability, exact format/hash/authentication result and required dependency closure. `NSError` domain/code and provider status may explain the UI and schedule Retry; neither turns unknown into absence, authorizes overwrite or selects a winner.

The common repair source is the **repair union** of exact validated immutable descriptors/objects available from the private store, `NV Data`, or an explicitly selected backup. Missing entries never subtract from it. Complementary partial copies may repair one another. Never merge damaged bytes, synthesize a different payload under an existing immutable identity, or prefer bytes by timestamp. Preserve occupied damaged/foreign entries in place. Automatic provider repair is add-only; occupied damage uses stop-and-Save-As.

Background transport also checks canonical names from a fixed accepted local
history prefix in bounded metadata batches. Background checks cap that prefix at
complete acceptance batches already covered by the existing publication cursor;
new outgoing work stays owned by publication and its retries. This detects previously published
objects that ordinary enumeration can no longer list. A fresh unchanged observation
may reuse its checked hint only for that exact expected immutable identity; changed
readable bytes must match the expected hash. Missing names enter normal verified

Keep prior branches and the restoration link inspectable in history. Concurrent explicit restores may create two notes; no expiry/permanent-delete promise. Note History and conflict resolution retain their distinct Save as new note actions.
- Recently Deleted Notes uses a separate read-only viewer window, not a replacement mode for the ordinary notes list/search. Multiple ordinary windows share one collection/session/live model and per-note undo/redo; their query, selected item, layout/scroll and geometry are presentation state, not independent databases or action histories. Retain each note's remembered cursor location/length using last update wins, including programmatic updates, while open views keep independent live selections. This UI state is not a causal note edit or cross-Mac ordering authority.
- View observers must not duplicate model mutations, action registration or pending captures. Admission and UI callbacks revalidate captured note/root/generation and attachment identity; admitted model work survives view switching/closure. Closing the last view does not discard pending history. Follow the [input contract](#input-and-content-scope) across all views of the note. Validate the actual native focus/IME/teardown bridge through normal event delivery; sharing NSTextStorage neither proves that integration nor requires an NV-owned draft buffer.
- ActionRecordV1 and members form one group with exact before/after references, one undo scope, synced action-origin provenance, and a canonical antichain containing all maximal causal action parents represented by the captured applied scope frontier, including earlier dependent local pending actions. Every such pending parent is earlier in the same complete segment or already locally durable. Reject omitted represented maxima as well as invalid parents; received but unapplied objects and incompletely loaded history rows do not define this frontier. Optional compensation/restoration/native-coverage/merge references retain their exact evidence. Validate agreement against the writer's declared causal inputs, not receiver Current. Freeze metadata with note operations; retry cannot recapture it from newer values. Origin and scope-parent edges are data, not permission or arrival-time order.
- Command-Z uses the existing note/collection routing over a repository-derived causal candidate view. Consider validated meaningful actions from every origin in the requested scope. Exclude automatic recomputations/storage receipts and effects already superseded by applicable compensation. A single causally maximal applicable candidate may proceed automatically on any Mac. Multiple incomparable candidates, overlapping current changes or ambiguous redo descendants offer Review Undo/Redo with the candidates disclosed; never choose by receipt time, wall time, writer sequence or local origin. Never deserialize selectors, NSUndoManager, pointers or executable remote strings.
- Native typing undo remains fine-grained, subject to the shared router's causal eligibility check before any native entry is consumed. Range validity alone cannot bypass a later remote action or concurrent candidates; retain native groups for when they apply. Cross-launch/cross-Mac saved-edit and named-action undo appends guarded compensation preserving unrelated current changes. Partial native undo records remaining effects of captured groups without duplicate coarse undo. Named/bulk candidates revalidate wholly or apply nothing; staleness leaves causal eligibility unchanged and offers review.
- Native remaining-effect claims follow action ancestry. Incomparable claims require review; only all maximal claims being complete consumes the saved group. Prepare the remaining reversal against actual Current's represented note lineage, as specified in [Protocol](impl-proposal-5/Protocol.md#action-records-and-cross-launch-undo). Received records obey the same causal-candidate gate as local capture; native ranges alone supply no exemption.
- Undo creation requires its unchanged result or explicit reviewed choice; undo deletion uses fresh birth. Redo reverses the selected actual compensation/birth mapping, and the next Undo reverses that actual Redo. Scope-parent ancestry orders actions; separate compensation edges identify the reversed effects. A causally later independent action in the same scope suppresses the earlier redo branch even if that independent action is subsequently undone/redone; a concurrent action preserves it for review. Undo/Redo commands preserve the remaining eligible redo sequence. History remains. Durable note effect and causal eligibility transition recover together even without callback.
- Two Macs may prepare the same unique candidate concurrently. Each must revalidate its captured frontier and Current before admission; any admitted compensations remain separate immutable actions. Equal effects may converge, while competing descendants remain reviewable. There is no distributed exactly-once Undo, shared pop operation or mutable cursor to arbitrate the race.
- Ambiguity is relative to the requested direction's maximal candidates and their compensation families, not every retained fork in the scope. Whole-action families follow compensation links, not causal scope-parent links; partial-native coverage retains all relevant remaining-effect families. Include a competing sibling in the candidate's family even when it is in the opposite direction. An independent X observing concurrent compensations U/V can be undone/redone automatically when its own candidate/value checks pass; the old fork alone cannot force review. The earlier redo suppression and retained-history rules still apply.
- Reviewed compensation affects only its selected action, never consumes a sibling or consolidates equal-valued actions. If a sibling's inverse would now be a no-op, disable that attempt without advancing eligibility; dismissal leaves ordinary editing and other applicable Undo/Redo commands available. Undo of an actual reviewed Redo and subsequent Redo remain possible with fresh validation/review. Concurrent restorations retain distinct fresh births; reversing one must preserve the other, and reversing that deletion uses another fresh birth. No automatic compensation-equivalence or branch-resolution protocol is included.
- Invocation context fixes the semantics of the shared resolver/history presentation. Opening, previewing or canceling review consumes nothing; no generic recovery action may silently replace a pending Undo.

Approval may authorize a disclosed overlapping-field replacement, never bypass birth/format/admission/root/store/generation or whole-group checks, retarget a changed candidate frontier, or widen Current's represented input scope. Changed inputs/candidates require fresh preparation/approval. Missing evidence and no-op effects cannot be overridden into a completed Undo. This mode neither creates a synchronization conflict nor calls Apple setters/disposes NV alternatives. After admission, normal pending compensation persists despite UI dismissal; before admission, consent is ephemeral and never replayed after restart.
- Encrypt history/deleted previews/indexes at rest in encrypted mode; release view-held plaintext on lock. Preserve keyboard/accessibility and editor focus. No exact cross-device typing undo, full-history search or implicit parent for undoing an automatic merge.

## Root events, shutdown and transitions

- One root session owns rooted resources, provider lane, presenter and invalidations; local durability is independent. Same-object moves retain ownership. Positive forward provider identity may supplement rooted equality; negative/unavailable lookup never proves ordinary-local authority or deletion.
- Positive authority change fences provider work into a provisional successor around retained resources. Missing path, vnode delete/revoke, failed bookmark or provider/account ambiguity pauses provider effects until positive revalidation. No reverse lookup/domain search or automatic confirmed-loss cancellation.
- Root unavailability alone does not destroy local history or disable healthy local editing. Uncertain private association/ownership, local barrier failure, unavailable write key, lock or quiescing does. Re-open/Save Current Collection As/quit are explicit transitions, never pathname retargeting or receipt transplantation.
- One asynchronous quit/folder-switch owner finishes or explicitly cancels external-editor handoffs, quiesces new admission, forces admitted local note/action/parent barriers, persists required private state, settles or explicitly defers plaintext projections, optionally waits for captured provider objects, then fences/drains callbacks and releases ownership last. applicationWillTerminate performs no second save.
- After local durability, provider/file delay offers Quit Without Waiting, retaining unpublished objects and restart-reconcilable projection intent. Local note failure retains live work and offers Retry/verified current-notes recovery export, not a repository-only copy that omits pending work. Unsaved settings are reported separately; failed mandatory association/key cutover is not success. Derived materialization failure alone cannot block durable quit. Cancel resumes only healthy admission.
- No shared checkpoint CAS, whole-union retirement re-journaling, history deletion or current-checkpoint merge exists in segment collections. NVCheckpointInstallCurrentChanged belongs only to explicitly retained legacy/export callers.
- Repository Save As copies available history/files with unchanged collection/birth/operation/action identities and sealed bytes; it is not fresh-genesis conversion. It needs no source Application Support, unpublished work or wait for other Macs. A copy-only command leaves the active root unchanged; if the requested Save As includes switching, verify the copy first and establish a fresh private store/writer epoch and physical ownership. Portable causal-undo eligibility derives from the copied action graph. The copy shares historical lineage, not root authority or a distributed writer identity. A collection-ID match never silently retargets an existing session.
- A switch from the active source also preserves required private settings, latest/frozen pending inputs and admitted work. A background-prepared private copy is usable only after a serialized final source check. If newer source work arrived, keep the source selected and request a fresh preparation rather than abandon that work. This final handoff is separate from completing a repository-only byte copy.
- Before switching, reacquire the destination under physical ownership and verify its exact saved-history bytes against the checked private copy. Complete known history and required private inputs authorize the switch; unavailable repository extras remain separately reported and preserved at the source. Retire the unchanged source connection before selection installation. Until an uncertain installation is settled, retain source exclusion, the candidate and both repository owners. Resume the same installed selection's readback/barriers. A known unchanged result keeps or reopens the source; a durable new selection followed by an opening failure reports that the new selection needs reopening. Closing or crashing preserves both stores and lets normal startup inspect the actual selected record.
- Initial legacy migration, explicit current-notes export and key/profile conversion create fresh independently owned destinations. Capture coherent source after recovery/external settlement; verify complete genesis/import/snapshot/required plaintext output; provision/read back independent credentials; only then commit active private association. These current-state-only conversions must be labeled as such, never substituted for full repository Save As. Preserve source history/files/credentials until success and explicit cleanup. Source changes invalidate capture; no in-place conversion under an old writer. A repository-only copy is not recovery of unsaved/admitted work; retain that work until separately saved/exported.
- Rewrapping a passphrase adds a same-key descriptor, not revocation; retained old descriptors/secrets may still unlock history. Full key/profile change gets a fresh collection/key. Never update/delete source credentials when making an independent destination; ambiguous target installation preserves necessary credentials.

## Encryption and persistence formats

- Use AES-256-GCM with 16-byte tag, HKDF-SHA256 domain-separated object keys, random 12-byte nonces and reviewed Argon2id wrapping. Initial KDF: 64 MiB, three passes, four lanes, version 0x13. Unsupported/failing profiles never choose weaker fallback; legacy CBC/PBKDF2 stays isolated.
- [Encryption](impl-proposal-5/Encryption.md) pins the 124-byte envelope header, kind/suite/scope separation, ciphertext-envelope SHA-256 identity, bounded independent compression and descriptors. Authenticate before decompression/value/RTF decoding; check lengths/overflow/limits before allocation. Provider objects reject private kinds/scopes. Initial decoded ceiling is 64 MiB/object; never truncate.
- Set remaining note/record limits from realistic input sizes/rates and measured whole-note memory, editing and synchronous-search costs. Give the byte representation ample headroom for every supported note plus required before/after references and metadata; do not add incremental live-note paging or an oversized-note subsystem speculatively. Existing fixed wire/security limits remain unchanged pending measurements and explicit revision. Small notes can still produce long history: bound parsing/work per pass and represent required frontiers/manifests without an accidental collection-lifetime limit. Reject malformed/oversized input safely; neither presumed UI impracticality nor authentication permits unbounded allocation, silent truncation or omitted ancestry.
- Freeze Intel/ARM vectors and review composition before production writes. Public hashes detect accidental corruption, not provider forgery. Encrypted mode hides note/action data but exposes opaque IDs/lengths/kinds/counts/timing; it does not defeat withholding, malicious key holders or compromised unlocked Macs.
- Password-free collections must remain recoverable without Keychain or any separately held secret/key file. Their SQLCipher database uses the documented nonsecret key; page encoding is not confidentiality. Encrypted database keys derive from the existing CK under a distinct domain, with usable wrapped-key descriptors retained outside the DB and included in private backups. Password changes add same-CK descriptors, not a database rekey or a second password system. Provider key/profile conversion remains a separate fresh-destination operation.
- Remembered encrypted-collection keys use tested signed-app Keychain access, synchronization disabled and device-bound unlocked access. Remember on this Mac is not password-free mode. Provision add-only/read-back/validate before private association refers to an item. Keychain/filesystem are not one transaction; remembering failure leaves password unlocking available. Loss of every encrypted unlocking route can be unrecoverable; exports/rewrap do not erase provider/APFS/other-app copies.
- Preserve existing plaintext deterministic vectors: recovery key hashes domain NV unresolved recovery key\0v1\0, raw source UUID, uint64 big-endian NFC UTF-8 body length/body. Slot hashes domain NV unresolved recovery slot\0v1\0, key and uint64 ordinal; first 16 bytes get RFC variant/version-8 bits. Automatic preservation hashes domain NV automatic conflict preservation\0v1\0, source UUID, length-prefixed NFC title/body and sorted NFC labels with uint64 counts/lengths. Dates/filenames/provider IDs are excluded. Rich content requires explicit versioned domain/codec vectors.
- Retired indexes remain sorted concatenated raw 16-byte identities with canonical validation, derived from typed operations rather than authoritative archive tombstones. Legacy syncServicesMD, WAL/header/checkpoint IDs and archive epoch define no modern retention/causality.

## Backup, diagnostics and compatibility

- Finder Select All must include visible NV Data. A full repository copy preserves all available repository objects/descriptors and associated text files, including unknown/unimported files and historical/deleted/action data, not just current values. Source private state/unpublished work and other Macs are outside this copy's scope, not prerequisites or reasons to call it inadequate. Copy actual bytes; report unavailable objects, changed captured files and incomplete known dependencies honestly. Copying preserves available evidence even when editable recovery must await a missing dependency; it does not prove globally latest history. A current-row-only or current-text-only export is not a repository copy.
- A complete private-store backup also includes unpublished work/settings and pending recovery buffers/links. Use a consistent keyed SQLite backup or quiesced complete DB/journal copy; include encrypted unlock descriptors. Password-free backups need no Keychain/provider/original-Mac secret, even if selection metadata was lost. Restore revalidates ownership/root/key/bootstrap and uses fresh writer epoch; never restores physical permission. Remembered device-bound keys are not promised portable; encrypted recovery needs usable descriptors and a password/recovery key.
- The last public release was in 2011, using epoch-4 Notes & Settings. No segment or private SQLite format has been released; superseded development encodings require no compatibility branch or migration. Keep epoch-4 opening/journal recovery and explicit export. Export writes genuine Notes & Settings at the legacy destination: current state, not history or an old-client live mirror. Segment/private formats need no epoch-4 readability. Foreign legacy archives in a segment root are preserved/reported, not adopted.
- Diagnostics allow closed operation IDs/counts/status/error domain/code, never text/titles/paths/bookmarks/provider/account IDs/keys/decrypted history. No Spotlight/Quick Look encrypted-history leak. Audit existing logging; this is not a claim the source already satisfies it.

## Verification and unresolved release gates

The initial plaintext value encoding preserves exact stored label-token spellings and uses raw UTF-8 ordering/equality for canonical sets and per-token merge membership. Case-insensitive label lookup/search is a separate host index, not a portable value-identity rule. Display dates retain finite binary64 seconds from NV's 2001 reference epoch; they never order causal history. The [first-save contract](impl-proposal-5/plan/first-save-reopen-contract.md) records the concrete encoding and its test/implementation boundary; later record families and full storage qualification remain open.

The [TLA coverage map](tla/Proposal5-Coverage.md) and [verification plan](impl-proposal-5/Verification.md) identify bounded checks for durability/dependency closure, causal deletion, bootstrap/current materialization, action recovery, merge/provenance and shared file/lane guards. These are not whole-code refinement, crypto/API proofs or arbitrary-history theorems. Retired checkpoint/WAL results do not prove modern authority merely because IDs match.

Remaining bridges include installer→reducer→restart, full root/private-state/key/close lifecycle, protocol-copy retirement plus Apple disposition, native partial/scoped undo and projection feedback. Co-add stays disabled. Concrete codecs/crypto/Keychain/signing, file generation/metadata/locking, crash/power-loss, current-row launch performance, UI/accessibility and materialized-backup checks remain release gates. Planned checks and SKIP/OBSERVE are not passing contracts.

The [native undo experiments](impl-proposal-5/Native-Undo-Experiments.md) add concrete AppKit observations and bounded partial-coverage/index-handoff checks. They do not prove the actual editor/segment bridge or adopt coarser native undo following a remote body update. First investigate registering external changes through supported undoable editing paths, testing earlier/subsequent typing, Undo/Redo and shared views against the existing causal eligibility rules. Receiving history or registering a native adapter must not author duplicate NV operations. Do not infer persistent user-action identity from group notifications, or automatic inverse-range rebasing from text-change notifications. The Undo Saved Edit fallback after a remote update remains unaccepted.

[Apple API Contract Validation](Apple-API-Contract-Validation.md) records measured limits. No historical xattr/identifier portability, global join barrier, provider ordering or cross-Mac lock is assumed. Accepted-history loss detection is the adopted retained-history-pin policy in [storage and ownership](#storage-identity-and-ownership) and [ADR 0016](adr/0016-repair-from-validated-immutable-copies.md), not an outstanding choice: validate exact objects/closure, then commit retention, acceptance, pin and dependency wakeups atomically before acknowledging durability or publishing incoming history. A surviving pin exposes a missing accepted leaf independently of derived current rows. Loss of all independent evidence still cannot establish otherwise unobservable rollback; the pin is not a globally complete remote frontier.
