# Proposal 5: proof priorities and model disposition

This is the coverage map for [implementation proposal 5](../impl-proposal-5/README.md). The specification and ADRs now adopt proposal 5; proposal 4 is retired. A passing proposal-4 checkpoint model is not a proof of the segment protocol. Here “checked” means exhaustive **bounded** TLC exploration, not TLAPS proof for arbitrary histories, implementation refinement, or verification of Apple's APIs.

The [whole-active-set audit](Storage-Protocol-Audit.md) lists the critical compound obligations, reproduced model/assertion errors, corrections and remaining gaps. Read it before treating adjacent green families as an end-to-end argument.

## Most important obligations

| Priority | Required property | Executable coverage and remaining boundary |
| --- | --- | --- |
| 1 | Every locally durable change survives restart, including installation before callback; its entire causal closure remains available, detectable if a pinned local leaf is later lost, and publishable without provider progress | `ImmutableSegmentDurabilitySafety` checks unacknowledged installed payloads explicitly. `SegmentDeletionSafety` checks dependent-edit/delete restart and transport. `LocalDurabilityLaneIndependence` supplies admitted-work progress without provider fairness. `RepositoryRepairSafety` adds split exact-copy/pin/activation ordering and missing-local/provider closure outcomes. These are complementary checks, not an `INSTANCE` refinement from real filesystem calls or Local State bytes. |
| 2 | Durable action metadata and every affected note recover together; Undo/Redo is portable across validated action origins, preserves unrelated changes, rejects stale/partial groups, and targets the actual compensation/restored birth | `SegmentActionRecoverySafety` checks finite values, split installation stages, compensation, crash and peer application. `PortableCausalUndoSafety` checks causal candidate ordering, command-relative ambiguity and private-state rebuild. `ConcurrentUndoExecutionSafety` uses the same pure reducer for dynamically authored concurrent compensations, reviewed continuation/no-op refusal, fresh births, independent-family commands, stale consent/completion and peer/recovery effects. `NativeUndoSpanSafety`, `UndoHistoryHandoffSafety` and `ReviewedUndoSafety` retain partial-coverage, native/index and invocation checks. This is not a full installer/peer/AppKit refinement: actual codecs, native family attribution/crossing groups, arbitrary action graphs and text remain gates. |
| 3 | Explicit Delete remains distinct from unexplained file absence; old deletion cannot erase restored or replacement files; concurrent edited content survives | `SegmentDeletionSafety` covers causal/concurrent Delete, restored birth and both crash hosts. `SeparateFileDeletionSafety` is strengthened to require the local command barrier before exact-incarnation removal. No model establishes physical identity from a filename/xattr or requires remote deletion receipt before local admission. |
| 4 | Automatic merging preserves independent fields, uses a unique best common base, declines unsupported heads, retains provenance, and cannot publish a stale prepared view | New `SegmentMergeSafety`: actual finite DAG ancestry, two observers, concrete two-field merge values, criss-cross bases, equal values, delayed third/dominating heads, a locally persisted user edit and out-of-order peer receipt. Full safety scenarios include root/input changes. A strictly decreasing progress rank is checked separately from convergence. The existing Python reference vectors check the LF kernel; the graph model does not prove arbitrary text/rich-content semantics or actual projection echo suppression. |
| 5 | Startup never converts incomplete/foreign input into editable emptiness; derived rows cannot override a durable tail or own private settings | New `SegmentBootstrapSafety`: two-note initial import, independent snapshot page/root delivery, local persistence, read-only preview versus editable publication, foreign input, one crash/root-generation change, and returning/materialization-rebuild cases. Foreign/authentication classification is an environmental input. Private settings survive materialization rebuild, but Local State's byte codec, credential cutover and real settings-save failures are not proved here. |
| 6 | Every Apple disposition has the exact note/copy segment barrier and exact installed file generation, and covers only the selected/captured members | Retain `UnresolvedVersionResolutionSafety` / `CrossMachineConflictDispositionSafety` as scoped-disposition components. Their abstract local durability input must be implemented with the dependency-closed segment barrier. They do **not** yet compose segment action records, slot retirement, real file installations and restart into one proof. This is a required remaining bridge, not a green release claim. NV-head copies separately adopt representation-only disposition. `NVConflictCopySafety` checks reciprocal copies, unchanged source selection, exact attention scope, later descendants/copy edits/deletion, durability and one crash. Its valid payloads and complete local barrier are abstractions; it does not close the Apple/installer/codec bridge. |
| 7 | Root/key/store changes never retarget pending effects, lose the only decryptable copy, or let provider/materialization failure prevent otherwise safe editing/close | Reuse the relevant root/current-file guards and local-lane properties. The new bootstrap/action checks cover specific generation/materialization cases, not full encrypted migration or quit. Bounded segment-specific lifecycle/cutover composition remains required before release, including source-preserving rekey/Save As, final external-edit and observer draining, private-store ownership during offline editing and known root contention. This is a coverage gap, not a transferred proof. |
| 8 | Independent imports, restore slots and backup/rejoin cannot silently alias unrelated files, forget history or declare a partial backup complete | The earlier identity experiments preserve the indistinguishability counterexamples. Four [co-add labs](CoAdd-Policy-Experiments.md) compare import intent, occupancy-event tokens, late deletion/restoration and historical-hint revalidation. They expose useful conditional rules and unavoidable observation ambiguities, not a composed protocol or an adoption decision: co-add remains disabled. Hints can reorder inspection, not establish permanent identity; unnecessary hint-based restarts can exhaust a pass. No positive Apple UUID-association assumption was introduced. The adopted private retained-history pin makes surviving Local State name missing required leaves; `RepositoryRepairSafety` rejects incomplete repair claims and destructive overwrite. Finder visibility, materialized backup bytes, encryption, arbitrary frontier DAGs and actual backup restore still need concrete tests; no TLA invariant proves UI selection or provider disclosure completeness. |

The four buildability-audit decisions now have focused coverage: `SegmentMergeSafety` separates ordinary Current-only note predecessors from global causal knowledge; `SegmentDeletionOrderingSafety` handles overlapping Deletes and retractable preservation; `ProjectionStampSafety` checks bounded provenance decisions under independent body/metadata/history observations; `RepositoryCopySafety` preserves available history without private-state prerequisites. The latter two assume validated digests/association or exact captured object tokens, not Apple delivery, physical identity or a whole-code implementation. Actual projection/import and copy/restore integration remains mandatory.

## Reading the new checks honestly

- Safety configurations allow arbitrary stuttering/provider delay. Convergence is conditional on its explicitly named fairness premise and finite input bound, never on elapsed time or Apple's upload status.
- Each new family has assertion-specific broken policies and reachable success/failure/restart witnesses. A parser error, timeout or wrong invariant does not satisfy a negative control.
- The merge progress argument checks natural-number bounds, a decrease on every progress action, nonstuttering progress availability while rank is positive, and agreement at zero. Only one root change and one optional user edit can increase the rank; a separately checked environment budget decreases on those events. Aggregate weak fairness is sufficient for this finite graph, not a production guarantee under endless editing. Smaller direct temporal checks run by default; the optional full three-head temporal check also completed, but takes substantially longer. This bounded ranking argument is not a TLAPS certificate.
- New/bootstrap, returning/private-materialization, edit/bulk/restore, portable action-order/redo/private-loss, merge/third/dominated/ambiguous/equal/conflict, overlapping-Delete, stamp, repository-copy and repair scenarios are separated to avoid multiplying unrelated state dimensions. There are no TLC `CONSTRAINT`s, depth cutoffs or simulation-only green results. Scenario exclusions are stated in each module.
- The concrete LF merge vectors and eventual Objective-C/crash tests remain necessary. These models do not establish cryptographic soundness, file identity, provider availability, cross-file atomicity, bounded history growth, or globally complete backups.

Executed counts, artifacts and remaining implementation tests live in [Verification](../impl-proposal-5/Verification.md). Read the specific property and its fixture before promoting a checked example into a general product claim.
