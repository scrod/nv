# Separate WAL durability from provider work

Status: accepted.

NV keeps host-local WAL append and barrier synchronization on a serial durability lane separate from the serial provider lane used for coordinated scans, materialization, note-file mutations, and checkpoints. Provider work may block for network access, but it must not block the UI or delay later local WAL durability. `WALController` creates, synchronizes, and deletes the Application Support WAL through local durability operations; there is no provider-visible journal namespace or claim handoff.

`JournalLaneIndependence` checks the headline progress obligation with no fairness on provider work: after provider completion is permanently disabled, weakly fair local append and barrier-sync actions must still make every admitted edit durable. The model covers only this local-lane obligation.

Each opened directory has one root-session incarnation that owns its rooted-directory reference, provider lane, presenter, cancellation/availability state, host-local WAL descriptor, and independent note/artifact dirty generations. Detached current-visible transactions validate root-session, note-content, and structural generations and may commit only while that same incarnation remains active and available. Late completions from a replaced, unavailable, or closing incarnation are discarded without a separate global generation counter.

The session registers one presenter for the root directory, not one presenter per note. Useful root/direct-child/version/ubiquity callbacks only mark retained evidence dirty; every accommodation is acknowledged exactly once, and optional reader/writer relinquishment is acknowledged promptly with no reacquirer while NV has no temporary state to surrender. Provider work receives copied current-visible inputs or copied note-file intents and returns immutable results. It never retains a mutable live `NoteObject`; construction and atomic publication remain on the main thread through the existing directory transaction commit.

A verified move retains the root session and structural generation when rooted identity still names the same directory and any available forward File Provider item/domain pair remains equal. Candidate URLs come only from the rooted descriptor, presenter callbacks, file-reference URLs, or bookmarks. A positive provider authority/account change instead fences the old incarnation and creates a provisional successor around the continuously held rooted descriptor, directory lock, open local WAL, and pending obligations. The successor cannot publish provider-derived results until positive namespace/authority revalidation promotes it. Ambiguity leaves it provisional and retryable.

Provider-authority uncertainty and local WAL durability remain independent. When no separate current positive ubiquitous-item evidence exists, failed or ambiguous forward provider discovery leaves the root unclassified and freezes provider-derived publication, but editing may continue while rooted identity, WAL association, append, and barrier synchronization remain valid. WAL append/outbox/barrier failure or inability to validate the WAL/root association selects the existing durability reason, urgently drains already admitted records, and blocks further edits until positive revalidation and a successful barrier. Suspension and lifecycle quiescing reuse the one authoritative `NotationController` mutation-admission check with independent reason bits.

The root session monitors its existing directory descriptor for vnode delete, rename, and revoke events. No negative observation proves deletion: missing paths, vnode unlink/revoke, deletion accommodation, stale bookmarks, provider unavailability, forward-lookup failure, eviction, and same-item replacement all enter root-continuity-unavailable state unless existing positive evidence re-establishes the same rooted object and provider pair. NV never enumerates a provider domain or calls `getUserVisibleURLForItemIdentifier:` to locate the root, never interprets a negative provider error as disappearance, and never automatically cancels the session as `confirmedGone`.

Root-continuity-unavailable state freezes provider publication. It blocks editing only while the root/WAL association cannot be positively validated. Retry reruns the existing positive checks. **Re-open from Disk**, collection abandonment, or quit explicitly ends the old session while preserving any unavailable host-local WAL as recovery evidence. **Save Current Collection As…** may explicitly end it and retire the old WAL only after the unattached destination's exact checkpoint and required file export are verified. NV adds no cross-root reconciliation, WAL transplant, deletion classifier, ordinary-local authority proof, or reverse-provider retry state.

Normative requirements: `AUTH-01`, `DUR-01`, `ROOT-01`, `WAIT-01`.
