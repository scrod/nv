# Keep Spotlight out of storage correctness

NV will not use `NSMetadataQuery` or Spotlight to gate startup, reconciliation, rebuild, dirty clearing, or a current-known claim. Apple documents `NSMetadataQuery` as metadata search, but does not give it a bounded completion time or a complete, exact File Provider snapshot contract; disabled, excluded, rebuilding, or damaged Spotlight state therefore cannot be allowed to suspend NV's storage lifecycle.

The authoritative discovery path is a coordinated shallow `NVRootedDirectoryCatalog` projected into disjoint note and NV-artifact sets. Exact `NSFileVersion` metadata is enumerated for every authoritative note candidate retained from the current note catalog, live model, last accepted note catalog, and presenter move/version callbacks; only changed candidates require content materialization. The artifact projection is limited to the fixed checkpoint, journal and lock names plus hidden `.nv-write-<UUID>` residue. A visible `Title (conflict recovery <UUID>).ext` remains an ordinary note candidate. Artifact status/recovery work cannot delay or complete the note generation. Two independently produced note-catalog/all-candidate-version observations still form the exact provider fence. Discovery failure makes that projection incomplete and preserves its dirty/evidence obligation under the existing fail-closed rules.

The initial implementation omits `NSMetadataQuery` entirely. A later implementation may use it only for advisory progress or wakeups whose absence, delay, or incorrect/incomplete results cannot alter publication, recovery, resolution, cleanup, or UI availability. The TLA+ models already abstract discovery as delivered candidates and exact fences, so this decision changes an environmental implementation input rather than any modeled state transition or safety predicate.

Normative requirements: `DISC-01`, `PUB-01`, `CAP-01`.
