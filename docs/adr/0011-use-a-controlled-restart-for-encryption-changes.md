# Use a controlled restart for storage-format changes

Changing the database passphrase, encryption, or first-class iCloud storage format also changes the checkpoint/journal contract, so it cannot be an ordinary live preference mutation while one process-lifetime WAL remains necessary. NV freezes editing, settles current obligations, installs and verifies a complete old-format checkpoint, and retires the old journal only after its applicable durability barrier.

For an ordinary encryption change, NV atomically installs the same complete store under the new encryption settings and restarts before accepting edits. When entering first-class iCloud mode, it instead exports every live note through the plaintext writer, verifies an unchanged provider catalog token across the export fence, installs the complete unencrypted checkpoint, and restarts with a fresh journal. A selected folder moved into iCloud triggers the same blocking conversion. Until the final install, the complete old-format checkpoint itself identifies an incomplete transition; retry reruns export idempotently and preserves divergent files, so no migration-phase ledger or intermediate unreleased epoch-5 compatibility path is maintained.
