# Separate current materialization, private state and visible history

Status: accepted.

Segment collections keep exact immutable history, required Local State and derived current rows as distinct logical roles in one private encrypted SQLite database. Local State owns settings, root association and retained-history evidence. Current rows include complete note values and ordinary-edit authoring context. Portable action-origin provenance belongs to retained action records, not private state (see [ADR 0015](0015-retain-history-and-use-compensating-undo.md)).

There is no packed startup cache. The [equivalent-load benchmark](../impl-proposal-5/plan/remaining-storage-validation.md#startup-remove-the-packed-cache) did not justify a second current-state representation. Remove its format, delta log/pruning, batch tokens, construction worker and publication transaction. The [fast-start contract](../impl-proposal-5/LocalStore.md) retains indexed acceptance catch-up, atomic current-row/context materialization, consistent startup capture and final owner/view-generation checks. Healthy launch never requires scanning unbounded history. Invalid materialization may require exceptional reconstruction; known history damage is not excused by valid current rows. Transactions protect atomicity, not reducer semantics.

Provider snapshot roots/pages remain immutable protocol objects with bootstrap/closure validation requirements. They are not directly trusted private current rows. The database and SQLite sidecars stay exclusively in Application Support; use consistent database backups and never exclude the whole file as disposable derived data. Database-key lifecycle/production SQLCipher qualification remain separate release gates.

One actor-confined connection owns each live private store. Its checked opening context supplies the fixed schema/header/descriptor binding throughout that connection's lifetime. Physical checks surround synchronous turns and commit; failure blocks the operation, with retry requiring positive identity of the same held resources. Actual mutable-record consumers, history diagnosis and generation checks retain their existing responsibilities. Required private inputs are checked again around exceptional reconstruction. Historical committed receipts retain their established completion behavior after orderly close. This [connection-bound reuse](../impl-proposal-5/plan/phase5/private-connection-reuse.md) removes repeated schema queries and per-statement filesystem checks while preserving the ownership, recovery and receipt boundaries.

Required provider history lives in the ordinary visible NV Data directory so Finder Select All includes it. Do not hide it as a package/alias or maintain an apparently authoritative compatibility archive. A full repository copy preserves available NV Data and associated text files/history; Application Support, unpublished work and other Macs are not prerequisites. Save As preserves exact objects and identities, not a current-state-only genesis. Private local-store backup separately includes unpublished work/settings. Report unavailable bytes/dependencies and credentials needed for recovery without claiming globally latest history or expanding copy scope.

Keep Notes & Settings naming and epoch-4 serialization only for legacy opening/recovery and explicit current-state export to a separate legacy destination. The last public release was in 2011; every segment/private format remains unreleased, so superseded development layouts require no compatibility branch or migration. No live mixed-version mirror is promised. This avoids conflicting authority and accidentally exposing encrypted data for an old application that cannot understand segment history.

The later [aged clean-exit benchmark](../impl-proposal-5/plan/aged-current-row-startup-validation.md) shows that physical locality still needs qualification: table order and bounded temporary allocations are required, but a current-table rewrite can reuse scattered free pages. The production [private-row format](../impl-proposal-5/plan/private-current-row-codec.md) now specifies bounded zstd/dictionary decoding and atomic dictionary/row installation. Dictionaries remain derived local metadata; provider snapshots and envelopes retain their own contracts. Returning open reuses its checked complete capture once under fresh fences instead of maintaining another cache. Cold/locality measurements, alternative geometry and physical read-ahead remain qualification work. A physical read hint would contain no current values or history certificate and must be safely dispensable. The [opportunistic full-VACUUM policy](../impl-proposal-5/plan/clean-quit-locality-strategy.md#adopted-opportunistic-full-vacuum-policy) permits occasional healthy-store idle compaction subject to measured eligibility and safe-interruption qualification. The explicit headless operation has bounded admission and exact-job cancellation/settlement; automatic scheduling remains disabled pending whole-store measurements. It does not adopt SQLite auto-vacuum mode, mandatory quit compaction or a renewed packed format; fresh-row results do not establish packed-equivalent performance for every aged store.

Normative requirements: CKPT-01, START-01, BACKUP-01, CRYPT-01.
