### Findings that changed the proposal

The first ordered-delete run produced a seven-state crash counterexample:

1. Admit an edit and then a delete that observes that edit.
2. Persist/acknowledge the delete while the edit is still only pending.
3. Crash; the volatile edit disappears.
4. Recovery rejects the delete's incomplete dependency closure and brings the original note back.

The fix is not “trust the delete anyway.” Local acknowledgment must secure every parent, either in already retained objects or earlier in the same atomic segment. Received children can be stored out of order but cannot be applied without durable parents. `earlyDependentAck` retains the broken rule and must violate `AcknowledgedHistorySurvivesRestart`. [Protocol](Protocol.md#admission-sealing-and-durability-without-a-second-wal) now makes this a production barrier.

Other controls demonstrate why the remaining requirements exist: acknowledging before directory durability, empty serialization, snapshot-only recovery, clearing a newer pending generation, pruning history after materialization, gating local saves on provider availability, equating external absence with Delete, discarding concurrent edits, reusing a deleted birth for restoration, applying a child without parents, unlinking a replacement, and unlinking before durable Delete all fail their designated properties.

The expanded models led to three additional clarifications in [Protocol](Protocol.md):

- Recovery and later publication use verified installed bytes plus dependency closure, even when the original acknowledgment/callback was lost. Requiring the old callback would strand durable work after a crash. Both durability recovery and cross-host action-delivery controls reject that mistake.
- Action before/after references must agree with the same frozen note-operation group, not merely be authentic or refer to valid IDs. Validate received records against their declared causal inputs, not the receiver's current state. Persist action-origin provenance and per-scope causal parents in the action record; no private undo owner/cursor is an eligibility authority.
- The shared physical-deletion component now explicitly includes the local durability prerequisite that the proposal already required. Previously it proved exact-incarnation selection alone; its passing result did not establish delete-before-unlink ordering.

These are stronger executable obligations and implementation clarifications, not new user-visible policy. Self-review also corrected a restore fixture: a remote intervention now edits the surviving other note, not the already-deleted birth. That modeling error required correcting the fixture and its concrete-value assertions, not changing restoration semantics.

The model checks native-to-model **ownership obligations**, not native implementation: immutable capture data and action cursor settle together, admitted work survives view closure, callbacks remain bound to captured note/root/attachment/generation, and observer notifications cannot create extra actions. This does not mandate that adapter, model normal focus transfer, or prohibit all provisional-text recovery designs. Controls/witnesses exercise actual mutations and transitions, including undo after both original views close following the edit, rejection after a remote generation change, and installing Y during X's draft. It does not infer IME completion from a view flag, prove NSTextStorage object lifetime, or compose provider transport/real segment bytes. Its cursor is an abstract command position, not the remembered caret range.

### What these checks do not prove

These are bounded checks, not a theorem for arbitrary numbers of notes, devices, edits, keys, or crashes. The models are complementary; they are **not** connected by an `INSTANCE` refinement mapping or a production-code refinement proof. Initial births/base payloads are given as valid in the durability/deletion/action fixtures. The new bootstrap fixture separately checks a concrete two-note import/preview/materialization boundary; independent simultaneous imports, arbitrary snapshot selection and codecs do not emerge from that fixture. The physical-file fixture deliberately abstracts exact positive association into one original/replacement token; it does not establish an Apple identity guarantee.

The reducer uses explicit finite values, and its properties independently require the concrete edited/conflict/restored/untouched results. It does not implement arbitrary text merging, real deterministic UUID hashing/slot allocation, rich content, or the full resolver. `EqualHistoriesAgree` is only an update-path consistency check; the separate concrete-value assertions and mutations provide the substantive deletion checks. Scope and oracle limitations must remain in future reports.

The original two models' claims remain unchanged in scope: their Restore action does not implement an undo stack/UI, and their payload is not an action-record/note pair. The action model explicitly couples finite action fields and note values; it does not cover native partial typing, arbitrary scope/origin forks or all multi-action interleavings. The merge model now distinguishes causal knowledge from note ancestry and checks ordinary Current-only editing of incompatible heads as well as represented-merge editing; it does not implement the LF algorithm or real projection feedback. Its both-input assertion applies to merged/equal Current, while separate conflict-scope and surviving-head assertions cover incompatible Current. The bootstrap model checks concrete finite import closure/materialization cases, not arbitrary snapshot codecs, key derivation or globally complete disclosure.

The portable-undo model checks candidate derivation from fixed finite action graphs, independent delivery/indexing and total private-state rebuild. `ConcurrentUndoExecutionSafety` imports the same pure `CausalUndoRules` reducer and dynamically authors/applies bounded compensations, continuing after review, no-op refusal, independent editing and crash. Its concrete-value oracle is separate from the candidate reducer. This is an executable selection-to-effect bridge, not an `INSTANCE` refinement between the full transport, merge, native-span and installation state machines. Whole-action scalar/fresh-birth semantics, complete imported records and the local installation barrier are abstractions; real decoding, partial-native family attribution, AppKit routing, arbitrary overlapping text/forks and actual file/directory/pin failure boundaries remain integration obligations.

Execution-model request plans bound the available user commands, not search depth. They need not be executed: safety permits indefinite stuttering, cancellation, stalled transport and races preventing the second concurrent Undo. Positive completion witnesses must actually create both branches, execute the dependent commands, recover and apply them on both hosts. The temporal run assumes fair local settlement/recovery and per-object receipt/application, never user approval. Model command slots are finite allocation abstractions; retry identity/crypto-byte sealing and restart origin allocation remain covered by their separate rules/tests, not proved by reusing a slot after an uninstalled attempt. Receipts can be parked before dependencies; imported acceptance abstracts its complete local barrier. No whole-history or unconditional cloud-progress claim follows.

The ordering model deliberately keeps its two-Delete/extension histories separate from installer/filesystem dimensions: accepted inputs are already dependency-closed and retained across its view restart. Its concrete E/F/H/P assertions and five broken reducers supply more than the equal-view consistency assertion alone. The stamp model allows arbitrary skew/reordering and missing/foreign values; it neither establishes physical identity nor promises eventual metadata delivery. The repository model checks copying a stated available inventory, not a globally complete distributed snapshot; absence of private tokens is a scope constraint, while the progress check and its private-required mutation test the lack of a private-state dependency.

The segment models' `materialization` state represents derived current rows, not a legacy database or separate Local State. The bootstrap model verifies independence of a finite private-setting value from derived-index loss; it does not prove Local State's persistence codec or credential cutover. The repair model treats exact-byte validation, a truthful health classification, the pin's required closure, positive provider-withheld classification and each filesystem barrier as inputs. It does not prove permissions repair, provider folder merge behavior, real corruption detection, arbitrary object graphs or recovery after all independent evidence is erased. Current-row launch speed, failure/quit UI, Finder visibility and complete backups remain concrete checks below.

Safety runs assume no provider progress. Each temporal configuration states its own premise: durability requires its named local steps; deletion retains its original per-action local/delivery/recovery premise as `PerActionFairSpec` and uses aggregate pipeline fairness in `FairSpec`, with independently checked rank/guard-preservation obligations; action delivery requires recovery and per-operation receipt/application, not fair user admission; local bootstrap requires Prepare/Publish and excludes root changes; merge uses aggregate progress fairness, justified only by its checked decreasing rank and finite environment budget. Only finitely many mutations exist in these fixtures; convergence means after quiescence and eventual delivery, not under permanently offline or malicious providers. Offline durability deliberately disables provider availability while requiring local progress. The shared lane model separately checks per-admitted-edit progress without any provider fairness. See the [audit's bounded convergence argument](../tla/Storage-Protocol-Audit.md#conditional-convergence-check-the-argument-not-only-the-outcome), including the distinction between checked rank obligations and a completed direct temporal run.

OS barriers, directory durability, exact immutable read/installation, truthful hashes/AEAD, positive rooted authority, absence of malicious authorized writers, and retained base history are environmental/concrete obligations. A model action named Sync does not test `fsync`, `F_FULLFSYNC`, APFS power-loss behavior, or iCloud. No new live-provider experiment was performed for this policy integration; the application build is a separate check, not API-contract validation.
