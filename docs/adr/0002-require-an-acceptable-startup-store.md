# Require a complete local startup view, not a provider-current database

Status: accepted.

Returning startup validates the private store's ownership, association, profile and key, drains ready Changes and their discovered required prerequisites, catches up the private current materialization, and constructs complete current notes and compact authoring frontiers from current rows. Required selection is independent of queue order. Independent optional snapshots stay durable and begin complete verification through the existing receive owner after successful checked host publication. Bootstrap, reconstruction, unfinished verification requests and known required-history checks still precede editability. The [fast-start contract](../impl-proposal-5/LocalStore.md) requires no mandatory full-history read on a healthy returning launch; bootstrap or invalid-materialization recovery may require it. The fuller history/candidate UI index may load later. It need not wait for the provider or materialize every plaintext file. Invalid derived rows require reconstruction, not permission to reset settings or omit durable work. Missing known history or private association requires repair/explicit recovery rather than editable emptiness.

A fresh device may preview a complete authenticated snapshot read-only after all its pages validate, but editing waits for its durable dependency closure and the complete genesis/import commitment. This is a narrowly scoped bootstrap preview, not an editability trap. A returning complete store ordinarily edits from local history despite generic provider unavailability. Work Offline is a distinct choice only when positively disclosed newer/required provider bytes remain unmaterialized or unreadable; it grants no provider-root access without root ownership. This wait applies only to evidence already disclosed during startup. Do not wait for provider discovery to decide whether to offer it, or suspend an already editable session on later disclosure. Eviction of an exact provider copy already retained locally is no missing-evidence gate.

Preexisting folders require explicit creation; empty listings and ENOENT prove no remote absence. Concurrent unrelated bootstraps require selection. Rebuild from Note Files is detached, stable-current-file salvage into a new collection, with explicit decoder/target/conversion choices and verified complete output. Source history is preserved. No newest-snapshot election or Spotlight gate is permitted.

Normative requirements: AUTH-01, START-01, CKPT-01, WAIT-01.

The headless `CollectionSession` joins the diagnosed private opener, initial
association gate, named-byte wait and checked publication. Provider acquisition
runs independently. Its publication reservation lasts through callback settlement;
ordinary transport is enabled only after success. Named-byte attempts use the
same bounded driver while its publication admission remains held. A complete
read-only bootstrap preview and complete editable import have distinct restricted
result types. [Implementation and qualification](../impl-proposal-5/plan/phase5/05-startup-and-root-reassociation-validation.md).

If an entered provider accessor prevents a fresh readability check, Work Offline
may consume the original exact named disclosure after checking the same live
root/attempt and complete local health again. This releases local publication,
preserves the pending input and grants no provider-write permission. A stale root,
changed selection or failed local health check still rejects the choice.
