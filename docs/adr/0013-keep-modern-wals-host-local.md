# Keep modern WALs host-local

Status: accepted.

Modern durability journals live only in the current user's Application Support directory, under `Notational Velocity/Recovery Journals`, and never inside or below the selected notes directory. Each `Interim Note-Changes.<journalID>` file is self-describing: its integrity-checked header carries its random journal identity, exact checkpoint-base identity, and a bookmark for the root whose edits it protects. Startup scans this local directory, resolves bookmarks, and treats every journal that matches the selected root as mandatory local recovery evidence. There are no `CFPreferences` active/retained claims, provider-visible journal files, cross-Mac journal ownership, or provider-version enumeration of journals.

One local WAL remains open for one editable root-session lifetime. Append and barrier synchronization stay on the provider-independent durability lane. A locally installed and exactly read-back-verified checkpoint may delete its covered local WAL immediately after Application Support directory synchronization; provider upload is not a cleanup precondition. If a crash leaves the WAL after checkpoint installation, startup either proves its records already represented by the accepted checkpoint or replays/preserves them conservatively before deletion. A failed or ambiguous checkpoint installation leaves the WAL intact. A successful **Save Current Collection As…** checkpoint may cover the frozen live work protected by the old local WAL because both durability artifacts are owned by this Mac; it does not copy the WAL into the destination.

The version-2 format changes only the WAL location and immutable header. Existing keyed `NoteObject`/`DeletedNoteObject` record archives retain their shared compression, per-record encryption, framing, and checksum behavior; new deletion records carry UUID/LSN with empty ignored legacy service metadata. Preferences and database metadata remain checkpoint-only. Mutation admission is the main-thread model update plus note/removal-record membership in the existing pending set, not synchronous WAL I/O; the current UUID/LSN is captured later without a second generation registry. Normal typing stays coalesced. Resolver, external-editor, lifecycle, and durability-suspension boundaries force immediate asynchronous record capture and barrier synchronization. Membership clears only after the captured generation's bytes leave the short-write outbox, its barrier succeeds, and the still-pending live UUID/LSN remains equal; an intervening edit stays pending.

RFC 9562 version 8 is reserved for deterministic conflict-note identities, so its UUID version is also the record's retirement discriminator. Every structurally valid version-8 `DeletedNoteObject` from a positively root-associated modern WAL unions its UUID into the checkpoint-scoped retired set. Exact-base recovery may additionally apply logical deletion; base-mismatch recovery applies retirement only and never removes or suppresses a live note or file. Checkpoint-current reconciliation journals the entire merged retired set in this form and barrier-synchronizes it before retry, because the no-longer-current accepted predecessor and any competing checkpoint may each be the only former durable source for part of the union. This bridges another current-checkpoint replacement and crash without adding a record type or coverage index. Cleanup requires a verified checkpoint containing every asserted retirement.

This deliberately gives up cross-Mac recovery of work that existed only in a WAL. Separate note files remain the provider synchronization representation. The WAL continues to protect same-Mac crashes, settings, deletions, and admitted edits not yet safely represented by their note files and checkpoint. Legacy exact-name journals found in a notes directory are still recovered for epoch-4 compatibility, but every new modern journal uses the local layout.

Normative requirements: `START-01`, `DUR-01`, `CLEAN-01`, `ROOT-01`.
