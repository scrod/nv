# Keep unclaimed provider-managed journals out of routine synchronization

An unclaimed provider-managed WAL may still have an active writer on another Mac because local file coordination and advisory locks do not cross machines. NV therefore catalogs the current file and every known local or nonlocal `NSFileVersion` fork as recovery evidence without normally materializing, replaying, appending to, resolving, or deleting them. Explicit recovery snapshots persistent version identifiers, validates each journal's complete prefix, and preserves otherwise-missing or differing states as deterministic nondeletion conflict notes. It never deletes or resolves evidence while a remote writer may still be active.

A same-host retained journal is not unclaimed: its current-host record proves only local ownership and the identity of an exactly verified covering checkpoint, while cleanup still requires the applicable later checkpoint durability. Ordinary local backup restoration automatically recovers exactly one structurally valid, unambiguous journal-recovery-eligible candidate while holding the directory lock; zero candidates require no recovery. Multiple eligible ordinary-local candidates authorize no automatic action, but explicit all-candidate recovery may reuse the same multi-journal replay and one replacement-checkpoint boundary because confirmed local authority plus the directory lock excludes every writer. Multiple different matching active claims likewise require explicit all-candidate interrupted-change recovery before a fresh claim may publish. Invalid, unavailable, or changed selected evidence fails closed. Modern journals do not add an inode lock. Partial or incomplete version enumeration preserves evidence and cannot declare recovery complete.

Normative requirements: `START-01`, `DUR-01`, `CLEAN-01`.
