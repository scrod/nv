# Identify journals with a host-local registry

Each checkpoint carries a random `checkpointID`; each journal generation carries an independently random, never-reused `journalID` plus the checkpoint base identity it extends and is named `Interim Note-Changes.<journalID>`. Rather than one global pointer or mutable dictionary, exact current-host preferences hold direct per-journal entries. `NVActiveJournal.<journalID>` contains the opened rooted directory's bookmark. When a locally verified checkpoint covers a closed journal but lacks upload qualification, `NVRetainedJournal.<journalID>` contains a schema version, that bookmark, and the exact covering `checkpointID`. The integrity-checked journal header remains the single source of its base identity. Bookmark resolution plus descriptor, header, role, and covering-checkpoint validation identifies journals this Mac may recover or later clean up, including for a temporary folder that is not the saved default, and only a matching stale bookmark is refreshed.

The normative epoch-5 persistence-format appendix fixes the tagged base-identity bytes, journal name/header/CRC, `.nv-root.lock` leaf, direct active bookmark value, retained dictionary keys/types, and ancestry archive shape. Those layouts are compatibility contracts, not implementation choices; malformed or unsupported values preserve evidence but grant no authority.

A fixed per-directory advisory lock must be acquired before a modern instance mutates that directory. Modern journals require no inode lock; only the legacy exact-name journal retains its compatibility lock behavior. A retained claim is written and synchronized before its active claim is removed; an interrupted dual-role record is resolved conservatively from exact local checkpoint coverage. Covering checkpoint identities are equality-only: any retained mismatch is mandatory recovery input, including when a crash merely prevented advancement to a later covering receipt. Any later exactly upload-qualified full checkpoint may delete every same-host retained journal reconstructed as represented and frozen into that receipt's journal coverage.

Successful or ambiguous namespace removal enters `deleting/pending-durability` while the claim remains. One successful root-directory synchronization advances every already validated pending removal in that directory to `deleting/durable`; claim tails remain independent. Later claim-removal or preference-synchronization failure retries only that monotonic tail without another checkpoint qualification. Restart does not promote a missing artifact directly to claim removal: after coordinated absence validation NV reuses the rooted-directory synchronization helper and retains the claim if it fails. A present or reappearing artifact remains claimed and cannot reuse a volatile old receipt. A same-host active journal with an exact valid header and zero record bytes may be removed without upload qualification only after append has stopped, all WAL obligations have drained, and removal is directory-durable before its claim is cleared. Unclaimed journals remain automatically recoverable after ordinary backup restoration and conservative recovery evidence under provider management. This removes persistent writer identity, writer rotation, and checkpoint ancestry without treating bookmark bytes, a host preference, or a local lock as cross-Mac authority or upload proof.

`CrossMachineGenerationSafety` checks the non-ancestral consequence directly: crashes before the first retained-claim synchronization, after the next checkpoint but before coverage advancement, or before advancement synchronization restore the last synchronized equality token and must take mismatch recovery before a later cleanup checkpoint may qualify both generations. A separate crash after local journal removal retains the captured deletion authorization so provider completion cannot depend on volatile post-crash receipt state.

Normative requirements: `AUTH-01`, `START-01`, `DUR-01`, `QUAL-01`, `CLEAN-01`.
