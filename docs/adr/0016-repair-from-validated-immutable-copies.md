# Repair from validated immutable copies

Status: accepted.

The visible selected collection folder, including `NV Data`, is the user's repository. Application Support is a private durable working copy and offline buffer that NV manages automatically. A complete private copy can recreate this Mac's known `NV Data`; a complete repository can rebuild a lost private store. Neither direction proves that an undisclosed branch on another Mac does not exist, and unpublished local work exists only in the private copy until publication.

Save As into a fresh destination gives exact verified local history its canonical
names. Damaged source occupants at those names remain untouched in the source and
are reported as preserved there; no additional archive directory is created. This
permits complete history recovery while honestly reporting incomplete coverage of
source extras. A copy report alone grants no activation authority.
An unsuccessful installation keeps that name reserved for its captured verified
bytes and reports the unmet requirement, preserving damaged source bytes in place.
The saved-history inventory keeps names/hashes at one accepted prefix, while
bounded publication reads supply payloads and verify complete consumption. This
reuses the existing accepted-history checks and keeps aggregate sealed-payload
memory independent of history length; inventory/report metadata remains proportional
to the number of objects. A later read failure preserves the source and partial output.

Classify damage by positive root/store identity, non-followed entry kind, access, exact validation and dependency closure rather than by presumed user/provider/backup cause or raw error code. Form repair input only from the union of exact validated immutable objects in the private store, repository and explicitly selected backups. Absence from one source retracts nothing. Preserve corrupt, foreign, contradictory, symlinked and wrong-kind evidence. Private-store repair uses a fresh sibling. Provider repair exclusively installs missing entries and leaves occupied damaged entries in place, offering Save As to a fresh destination.

An inaccessible source subtree or requested file produces a source/path report
while other explicitly selected sources may supply the exact missing evidence.
Continuation requires the original root permission; loss of ownership and valid
identity contradictions remain terminal. Candidate construction requires the complete
known accepted union. This isolates access failures without treating unreadable
subtrees as complete inventories or changing their permissions.

Private reconstruction carries historical pending-input capture bindings from all
contributing stores, including earlier repairs. Exact matching bindings coalesce;
conflicting private identities stop complete activation. Their descriptors remain
part of validated retained history. These bindings preserve readability of original
inputs while fresh physical checks and user decisions govern later effects.

The existing transport worker follows directory discovery with bounded checks of
accepted canonical names at a fixed local prefix, capped by completed publication
progress. A partially published acceptance batch is revisited after its publication
completes. This keeps outgoing retries separate from repair of earlier published
objects, using the existing cursor rather than another receipt registry. It can notice loss
after an earlier publication completed. Existing observation hints are reusable
only when they name the expected accepted identity; changed bytes are hashed.
The attempt-local cursor and restricted checked result add no durable inventory.
This supplies observations to the same repair/preservation policy, while complete
private-closure validation and fresh exclusive installation remain separate gates.
The tradeoff is additional background metadata work proportional to known objects,
plus the existing durable verification-request barriers around private membership
checks. Healthy startup and warm checks avoid decoding historical envelopes.
The collection's existing foreground-operation count gives that work priority over
new optional inventory turns. The existing timer revisits a deferred turn with its
cursor and retry budget intact. This prevents verification-reminder writes from
repeatedly invalidating a quiet Save As. An earlier admitted check may still force
one fresh preparation; final source comparison continues to count every write.

Individual missing objects, owned protocol subdirectories, and a positively same-root locally missing top-level `NV Data` are repaired automatically from a complete private retained closure after fresh generation/absence checks. Occupied corrupt or wrong-kind entries stop affected provider writes and offer Save Current Collection As…; healthy local editing continues. Retry reobserves the entry after external correction. The complete local closure grants no overwrite permission, and repair adds no displacement-reconciliation record. Exclusive creation retains its no-overwrite contract. No **Restore NV Data** control or consent state exists. **Work Offline** is offered only when the provider positively discloses newer/required evidence whose exact bytes are unmaterialized or unreadable, not for generic offline/full/permission/root errors. Repair a damaged private store by constructing a fresh sibling local-store ID, verifying complete closure, durably committing its association and retained-history pin, then activating it.

The pin records required descriptors and maximal accepted segment locators in the same private SQLite transaction that retains exact bytes and accepts their complete history; it is private accepted-history-loss detection, not a synced HEAD, undo cursor or receipt registry. Healthy launch reuses prior validated acceptance without rereading all old history. On-demand discovery of missing/corrupt required evidence invokes repair; an unread corrupt page need not already be detectable. Total Local State loss creates a fresh pin from the validated disclosed repository closure. A fresh-sibling database rebuild preserves available required private buffers and state as well as exact history, verifies closure, then durably activates the new association; a live main-database-file-only copy is not a backup. Synced note revisions and `ActionRecordV1` values, including scope-parent and compensation relationships, rebuild Note History and portable causal Undo/Redo; only transient native typing groups/selections are unavailable.

General snapshots v1 name exact accepted snapshot roots as retention parents in
the paged manifest. The capture freezes the accepted root frontier with its
acceptance prefix. Acceptance verifies protected root bytes and accepted context,
then commits dependency edges and removes only explicitly covered frontier tips
in the existing transaction. Previously validated parent closure is reused;
missing or unsupported parents wait or block through ordinary intake. Retention
ancestry preserves objects independently of represented note history, so a link
between differing logical cuts cannot select older note values. The parent set
may be empty within the same eight-category layout. All ancestor bytes and on-demand verification
obligations survive, while sequential snapshots avoid accumulating startup root
checks. Concurrent independent tips remain. This format change adds no private
table, sidecar, persistent validation cache or pruning rule. See the
[format contract](../impl-proposal-5/plan/general-snapshot-record-contract.md).

Protected accepted-history checks first commit a small private verification request and keep it through their final semantic validation. Failed damage-marker writes leave that exact obligation durable; opening replays it before publishing an editable collection. Successful verification settles its own request, while a committed damage marker remains repair evidence. Unfinished requests are required Local State in backups and repair. A replacement store must verify their original retained scope or prove an equivalent rebinding: an old local acceptance sequence cannot simply be interpreted as the same prefix in a new database. An unrelated crash with no unfinished request retains ordinary indexed startup. See the [verification recovery contract](../impl-proposal-5/plan/phase-4-improvements/durable-verification-recovery.md).

Provider-only failure pauses synchronization while a complete healthy private store remains editable. Work Offline applies only to startup with already disclosed evidence absent locally; do not wait for discovery to manufacture that gate or revoke active editing on later disclosure. Missing/incomplete/unwritable private closure suspends admission until exact repair, because provider persistence is not the local durability barrier. Complementary copies may repair one another, private first, including before any incremental republishing. If every source lacks the same required evidence, preserve what remains and require another copy or explicitly disclosed current-state salvage; no implementation can reconstruct or prove erased bytes.

The SQLite mapping preserves the original database/journals and attempts salvage on a working copy. Revalidate candidate immutable bytes and complete private record groups; an SQL recovery result is not accepted history or consent. Rebuild exact history plus available unique private work in a fresh database, reopen/verify its pin and unlocking route, then atomically switch the small selected-store record under ownership. Do not introduce a second per-edit frontier sidecar. Password-free backups need no secret; encrypted backups include usable wrapped-key descriptors, not merely device-bound references. Missing pending buffers/settings are reported separately from history loss; provider-only reconstruction is not complete private recovery. [Concrete mapping](../impl-proposal-5/LocalStore.md#sqlite-backup-salvage-and-replacement-activation).

For an explicit Save As switch from a healthy private store, the existing complete
fixed-state SQLCipher backup can prepare an independent candidate while editing
continues. Preserve every required private input and assign fresh private/root
ownership. If any source write intervenes, the final handoff may retain the source
and require a fresh preparation instead of maintaining another incremental transfer
protocol. An earlier successful comparison is only an observation; activation still
requires the serialized source/selection checks. See the
[P5.6 mapping](../impl-proposal-5/plan/phase5/06-repair-replacement-and-copy.md#fixed-copy-preparation-and-final-handoff).

The integrated handoff checks the destination's exact saved-history inventory under
its newly acquired owner, then checks and retires the original SQL connection in
one serialized turn. Selection obtains exclusion of the retired source and checks
its settled file/journal observation. An uncertain selection keeps that exclusion
and both roots until resumption or explicit close. Required private inputs and
known history must be complete; separately reported unavailable repository extras
remain preserved at the original location. No additional transfer journal is needed.

The selection owner checks cancellation before admission and at its final
pre-install boundary. An installed effect proceeds through normal durability and
readback settlement even when cancellation arrives afterward. A cancelled retry
retains the existing uncertain attempt; closing the verified candidate revokes its
live evidence while the selection owner retains its own pending exclusion until
settlement or explicit close. This reuses existing lifecycle state and preserves
both stores for ordinary reopening.
Integrated Save As retains its earlier final-handoff admission: activation runs in
a bounded task with independent cancellation and is awaited through settlement.
This keeps late caller cancellation from revoking already-owned handoff work.

Normative requirements: AUTH-01, START-01, DUR-01, ROOT-01, CLEAN-01, BACKUP-01, REPAIR-01.
