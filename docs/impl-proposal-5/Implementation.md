# Implementation work and lifecycle behavior

Part of [proposal 5](README.md). This is a production implementation plan, not a claim that proposal-4 abstractions already exist in the source. Preserve the current legacy path while bringing up segment collections behind an explicit collection-profile boundary.

## Ownership: reuse the current application, isolate the new persistence work

| Owner | Work | Must not do |
| --- | --- | --- |
| Main thread / `NotationController` | Admission, live notes, pending UUID/LSN sets, undo, immediate search, prepared-result publication, UI/lifecycle generation | Blocking provider/file I/O, crypto, full archives, synchronous waits for workers |
| One local segment-store lane | Immutable capture encoding/sealing, private SQLite acceptance/index/pin transactions, required state, derived current rows, recovery decoding | Wait behind provider coordination, use AppKit views, mutate live `NoteObject`s |
| One provider/root lane per open collection | Rooted provider access, coordination/presenters, discovery/download/publication, text projection, API status/revalidation | Acknowledge local durability, infer remote completeness, retarget a lost root |

Detached reduction uses immutable value snapshots. Initially schedule it on the local lane with bounded work units and give pending local durability priority; add another worker only if measured replay/reduction latency delays local barriers. A large bootstrap must yield between objects, not monopolize the worker indefinitely. Use SQLite rather than building a custom database/index engine; no general scheduler or configurable backend hierarchy is required. [LocalStore](LocalStore.md) fixes the private transaction, database-key, backup/salvage/activation and fast-start mapping. Password-free stores use its documented nonsecret key and never wait for Keychain; encrypted stores derive from CK and retain recoverable wrapped-key descriptors outside SQL. Implement no second password UI or routine database rekey. Repair works on a preserved DB/journal copy, validates immutable bytes and complete private groups, and activates only a reopened verified sibling through the durable selected-store record; retain originals on failure or uncertain completion.

Minimum new production responsibilities: an immutable segment/value codec and crypto composition, one local segment store, and one segment sync/reduction controller integrated with the existing notation controller. The [Swift implementation plan](plan/swift-storage-implementation-plan.md) places the portable values/algorithms and runtime in a small Swift package with an Apple adapter; it supersedes the earlier implementation-only restriction to a narrow crypto bridge. Canonical definitions live directly in Swift, without CUE or a schema generator. Extend value indexes for history/actions and add a pure conservative merge function; do not build a second history database, task framework, or persistence backend. Keep plain/public and encrypted suites in the same codec with explicit immutable profiles. Use existing `NVRootedDirectory`, pending sets, file-observation records, importer/exporter, and UI lifecycle owners where their actual contracts fit; do not create duplicate “pending changes” stores.

Each callback carries collection/local-store ID, lifecycle/root generation, and exact captured note/operation IDs. Under MRC, copy blocks and retain immutable inputs explicitly; do not pass mutable live notes or raw nonretained controller pointers to workers. A main-thread stale-result check is mandatory even after successful I/O. Close/cancel transfers ownership of outstanding buffers and does not deallocate a root while an accessor can still refer to it.

Maintain continuous local single-process ownership of the opened notes root and local store. Extend the existing descriptor/flock ownership approach; a provider file is not a distributed lock. Audit all `NVRootedDirectory` callers before confining an instance to a lane: note saves are not the only callers. Import/export, open-file handling, external-editor completion, database closing, presenter teardown, and credential/storage transitions must use the same ownership boundary. File-descriptor rooting remains path-independent across long paths and directory moves.

Keep root and private-store ownership distinct. A returning offline session must exclusively lock and positively associate its private store even when its provider root cannot be opened. It performs no root access/publication until that root's ownership and continuity are validated; known live root-lock contention is not bypassed. Retain any already-held root descriptor through same-object moves and handoffs. A single-store open acquires private-store ownership first, then attempts nonblocking root ownership on the provider lane and releases only resources it newly acquired on failure; it never waits on a provider while holding the local durability lane hostage. Test two simultaneous local opens, offline return, root reappearance and copied-store ambiguity before enabling this path.

## Admission and undo rules

One shared admission predicate combines independent reasons: local durability/key failure, lifecycle quiescing, startup incompleteness, and explicit locked state. Provider upload/download failure alone is not a reason. The check precedes mutation and undo registration; rejecting a command must not corrupt its undo stack or mark a note dirty.

Reuse `scheduleWriteForNote:`'s capture timing: 2.7 seconds after the last edit, with a 15-second first-pending-edit timer that further edits do not reset. Preserve forced lifecycle/resolver/external-editor boundaries. Schedule immutable capture and off-main persistence without making native undo grouping a timer, finishing composition merely to save, or changing synchronous search. These targets schedule work; only the complete local barrier acknowledges durability. The extra segment obligations are exact note/action coverage, newer-generation protection, and a local-settlement reconciliation wakeup, not new typing UX.

An admitted action mutates the live store and pending set immediately; admission is not acceptance into durable history (see the [lifecycle terminology](Protocol.md#admission-sealing-and-durability-without-a-second-wal)). If its later local barrier fails, preserve the admitted state and pause subsequent mutations while presenting Retry or a separately labeled current-notes recovery export; a repository-only copy does not save pending text. Do not roll it back to stale derived rows. Check size/format support before admitting a new unsavable value when the limit is knowable; never serialize it synchronously merely to perform this check.

Capture Current's exact represented revision set separately from the applied causal frontier in the shared mutation path. Ordinary typing, title/label/format changes, programmatic transformations, external-editor returns, native compensation and non-resolver historical field recovery replace only that set. Never fill note predecessors from all known conflicting heads. An explicit resolver choice carries a separately captured resolution scope; no boolean inferred from equal body bytes or opening the resolver substitutes for that action. Keep unresolved alternatives and separate conflict notes unchanged. A valid derived merge/equal-value Current already represents its named inputs, so editing it references those inputs only.

When local settlement makes a temporary Current-head pin releasable, enqueue reduction/publication through the same generation-fenced path used for incoming history; do not rely on another provider notification. Keep displayed Current and its represented input IDs paired. Revalidate both during admission even when the causal frontier is unchanged. The durability completion must not directly replay its captured body, and derived publication must not clear a newer edit. Test this wakeup with the provider quiet and a review open (`CompensationOverlapBridge`).

Undo is a new action against the current causal frontier, not erasure of a previous operation. Implement the [action-record and compensation rules](Protocol.md#action-records-and-cross-launch-undo), including per-scope causal action parents, exact affected values, preserved unrelated changes, fresh restoration births, and atomic action-record/note durability. Validated remote action records join the same portable candidate graph; arrival time never orders them. Route incomparable candidates or unsafe compensation through review without changing eligibility or silently discarding remote work. Concrete tests must cover local/remote title/body/tag changes, concurrent candidates and pending-deletion generations, not just editor keystrokes.

On incoming changes, the prepared reduction and any file effects are a single proposed publication. Before main-thread publication verify the live generation, root session, selected collection, and captured input frontier. Either publish all note/recovery/retirement effects and update dependent indexes/list state together, or publish none and recompute. Provider physical writes occur separately under their own expected snapshots; “atomic publication” does not claim a cross-file or cross-Mac transaction. User prompts happen before the corresponding decision is published; unrelated ready work can proceed.

Automatic preservation is derived, not an ordinary creation operation emitted on discovery. Recompute uncovered maximal source revisions against all applicable Deletes. D₀ concurrent with E followed by discovery of E→D₁ removes an untouched E copy from the live/index view; F extending E concurrently with D₁ remains preserved. No automatic retirement is written. Before retracting, revalidate that the candidate has no admitted independent edit or explicit copy; durable independent actions preserve their value across replay even when their original derivation is no longer eligible in the receiver's full history. Invalidate deferred editor/resolver/list results by generation without losing pending text. Retain segment evidence and treat leftover obsolete projections under the file decision matrix, not as fresh Imports or blind cleanup targets.

DeletionManager candidates retain the captured birth, file observation/absence, note generation and applicable-history inputs. Reappearance or changed input refreshes that candidate rather than reusing an old button response. If an incoming committed Delete settles it, remove the pending prompt atomically with that logical result; a later Restore explicitly creates a fresh birth. Deferred confirmation does not partially remove the note or hold unrelated ready segment batches. Adapt the existing object-pointer-based UI bookkeeping without granting those pointers durable authority.

## Startup and unlocking outcomes

| Evidence on this Mac | Outcome |
| --- | --- |
| Valid private association, unlocked key if needed, valid current rows and authoring context | Drain indexed ready work and catch up any acceptance/materialization gap, then load all current values/search data and compact ordinary-edit context. Publish under the final owner/history/view fence and enable input; historical queries remain lazy. Start provider discovery independently. |
| Current materialization itself invalid, complete retained local closure | Use the exceptional validated rebuild path, preserving required private state and corrupt evidence. This is not the normal current-row launch. |
| Private Local State missing/corrupt or root association unverified | Recover/confirm the association and report affected private settings separately. Do not trust derived rows as root authority or reset settings during materialization rebuild. |
| Entire private store/Application Support subtree missing; selected repository has complete disclosed closure | After explicit repository selection and positive root validation, create a fresh local store, Local State and writer epoch; receive/verify the repository before enabling editing. Rebuild Note History and portable causal-undo eligibility from provider action records; only transient native typing undo is unavailable. No user management of Application Support is required. |
| Valid returning local history; provider offline, full, or temporarily unavailable; no positively disclosed unread newer object | Permit local editing immediately after local checks and show sync status. Do not present Work Offline merely because provider progress is unavailable. |
| Valid returning local history; provider positively discloses a newer version or required object whose bytes are unmaterialized/unreadable | Bound the wait for those exact bytes, then offer **Work Offline** or **Save Current Collection As…**. Work Offline bypasses only this provider-evidence wait, not local recovery/key checks. |
| Keychain locked/unavailable or passphrase needed | Offer unlock; keep notes private and noneditable. Do not discard descriptors, recreate an empty store, or delete Keychain items. |
| New Mac with descriptor but incomplete genesis/import/snapshot/parents | Fetch asynchronously and show bounded progress. A complete authenticated snapshot may be previewed read-only. Retry/reopen or select another store; no editable empty fallback. |
| Unknown mandatory codec/profile, failed authentication, contradictory bootstrap | Preserve bytes and present unsupported/integrity/selection outcome; do not silently downgrade or merge unrelated collections. |
| Retained-history pin names a missing/corrupt local segment or descriptor | Preserve available live/recovered work; repair into a fresh sibling local store from exact provider/backup bytes. Do not claim a stale snapshot contains all accepted changes or permit forgetting that history to get past startup. |
| Private store is unreadable/unwritable/wrong kind, or Application Support cannot host a new sibling | Keep any complete recovered view noneditable, preserve evidence, and offer Retry or verified current-notes recovery export. Provider availability is not a local durability barrier. |

Returning launches do not wait for every remote segment or current text-file body. Indexed current-row loading plus compact authoring context and indexed acceptance catch-up establish immediately available state, not a globally latest-state promise. A new device may have to download substantial history before editing. The [equivalent-load benchmark](plan/remaining-storage-validation.md#startup-remove-the-packed-cache) supports removing the packed cache from the design; do not implement packing workers or cache-only bookkeeping. No mandatory full-history scan or epoch-4-format dependency is added to healthy returning launch.

## Conflict resolver and asynchronous operations

Preserve the agreed UI: clicking the persistent Conflicts badge swaps `LinkingEditor` out of its split-view position for `ConflictResolverView`. It is not a modal window/overlay and does not override `LinkingEditor` persistence. The resolver owns an `NSTextView` or equivalent read-only text presentation control. Its menu includes **Current** and disclosed conflicting versions; selecting an item immediately requests a read-only preview. An always-available **×** dismisses it and restores ordinary editing subject only to the independent admission predicate. [Conflict resolver mockup](conflict_resolver.pdf).

Show segment-head conflicts separately from Apple's unresolved file versions even if they share the presentation. A stable segment revision is identified by the protocol, while an `NSFileVersion.persistentIdentifier` is an operation-local provider handle, never a portable receipt. Per-note history may browse retained **NV operations**, but does not enumerate Apple's historical database versions or manufacture conflicts from old resolved note revisions. Conflicts derive from currently incompatible operation heads and currently disclosed Apple unresolved members. A successful automatic merge has an inspectable history/merge indicator, not a fabricated Apple conflict badge.

**Use this version** admits the selected body through the ordinary mutation path, keeping the source title/labels/identity. For segment heads, its observed-head parents express the disposition. **Save as new note** captures title/labels/body, uses the existing deterministic key/slot and exact-candidate checks, and durably couples the copy with the selected segment disposition. Later ordinary deletion retires that recovery identity; replay does not blindly recreate it. Current cannot be saved as a conflicting version.

For Apple versions, preserve the stricter existing four steps: (1) capture/validate selection and admit body/copy, (2) exact local segment/parent barrier, (3) exact separate-file installation, (4) coordinated source/member/root revalidation and Apple resolution. Use `NSFileCoordinatorWritingForMerging` for the final disposition as required by the existing API contract. The local barrier replaces the old WAL barrier; remote upload is not a prerequisite. Use-current/current-body disposition covers only the operation's captured unresolved set; save-as-new covers only the selected member. No version-removal API is added.

| Failure or delay | Per-item state and permitted work |
| --- | --- |
| Preview unavailable or selection stale before admission | That version cannot be chosen yet; leave other selections and × usable. No note mutation or provider resolution. |
| Capture/admission rejected | Preserve preview; show the actual admission reason. No automatic replay of the user's body choice later. |
| Local segment barrier pending/fails | The admitted body/copy remains ordinary pending work. Item says local save pending/failed; no Apple disposition or claim of completed recovery. Local durability failure may independently pause all mutations. |
| File install pending/fails after local durability | Item says file save pending/failed. × returns to editing; another edit creates a newer generation. The old operation cannot overwrite it just to finish resolution. |
| Source/member changes before disposition | Leave changed/new members unresolved. Do not repeat admission of the old preview or overwrite a modified/retired recovery note. Revalidate, then park as stale if applicability no longer holds. |
| Apple resolution fails or its observation is ambiguous | Retain the locally durable result and exact operation context while valid. Re-query/revalidate within the bounded attempt; no duplicate note creation solely to repeat resolution. |
| Resolver dismissed or another note selected | UI disappears; eligible background file/disposition work may continue. Its completion cannot reopen the view, change selection, or mutate newer content. |
| Retry budget exhausted | Park that item; badge remains. Re-presenting the resolver automatically starts a new bounded attempt for still-applicable parked work. There is no separate Retry button. |

Use a small finite retry budget per item/presentation, with backoff and a wall-clock attempt deadline. A deadline is a UI/scheduling boundary, never evidence that a provider operation failed, a version resolved, or a lock is free. One in-flight accessor is not forcibly considered canceled when the UI deadline expires; its late completion still needs full generation checks, and reopening must not create overlapping attempts for that item. Suggested initial scheduling values are three completed attempts within 15 seconds; validate UX with a genuinely stuck accessor. Do not run unbounded background retry loops.

After restart, reconstruct durable protocol copies/dispositions from segments; ephemeral Apple handles and old physical-install authority do not survive. Fresh enumeration may rediscover an unresolved member and reusable recovery copy. Reuse requires the exact live body and current file generation; UUID/tombstone existence is not evidence that the provider member was saved. Only a fresh successful unresolved-version query can clear Apple's badge. Segment conflict badges clear when current heads yield a valid conservative automatic merge or are represented by completed causal choices; new remote heads can make them return. Neither automatic merging nor ordinary history recovery calls Apple's resolution/removal APIs.

Track the badge's NV-head and Apple-member sources independently: an empty Apple query cannot dismiss unresolved NV heads, and a causal choice cannot clear Apple's unresolved set. NV Save as new note records representation only, with no implicit Keep Current or source mutation. Keep source-head reduction separate from the filtered unresolved menu/index; never use an empty menu as deletion or an empty body. The copy's exact evidence must bind its source revision and copy state in the codec, not rely on a mutable UI index.

On a completed NV copy, remove only its exact selected revision from unresolved attention and select Current when the operation still owns that presentation; retain other items and close ×. If no NV alternatives remain, clear only the NV badge source. Background completion after dismissal or another selection cannot reopen/retarget the view. Current is never removed merely because that revision was copied on another Mac. Explain the button as “Save this version separately and remove it from the unresolved list. This does not choose a replacement for the original.” Use this version remains the explicit source-body choice. Reciprocal saves can leave two recovered notes plus the original, including a duplicate of Current. Later source history may change Current under normal reduction; the copy itself cannot select a different source value. A completed copy's later edit/deletion does not reopen that historical conflict. Keep waiting/failure scoped to the existing per-item rules; do not hide an item before its durable copy/disposition barrier.

## History, Recently Deleted, and cross-launch undo

### Per-note history and selective recovery

Add a keyboard/menu-invoked **Note History…** action independent of the conflict alert badge, so history is available for an unconflicted note too. Reuse the read-only preview/diff presentation and editor-swap host without subclassing `LinkingEditor`'s persistence behavior. The view has an always-available × and shows Current, saved revisions from all known origins, named actions, and relevant automatic-merge descriptors. Indicate concurrent branches and distinguish author-reported dates from this Mac's receipt; do not call the ordering a globally complete timeline. Optional origin labels are not authenticated user attribution.

Do not populate the history list by replaying edits into a live note. Use the private index of exact operation IDs to request detached values; fence preview completions by selected note, entry, view generation, and root/store. Missing/unavailable history disables only that entry's mutation controls and remains dismissible. Cached local history remains usable offline after ordinary unlocking; fetching older entries must not block current-note editing, launch, or synchronous live-note search. Full-history search is not part of this feature.

The initial actions are:

| Action | Required behavior |
| --- | --- |
| Copy selected text | Normal copy from a read-only historical preview. Applying it later uses the ordinary editor path; there is no automatic background insertion. |
| Restore selected fields | Default to body only, preserving current title/labels; title and labels require explicit selection and preview of the resulting current note. Capture/revalidate Current before admission. Do not silently convert rich text or apply an old body over a newer edit when the preview became stale. |
| Save as new note | Ordinary fresh-birth historical copy with captured title/labels/format and collision-adjusted filename; record source revision and action identity for retry. Do not mark the original revision or any Apple version resolved. |
| Review automatic merge | Show base, both inputs and exact computed result, with algorithm version and changed-field summary. The user can retain it, recover a parent/selected fields as a new action, or save a separate copy. There is no unique implicit “undo merge” parent when two concurrent branches exist. |

An explicit **Keep merged result** records a normal user `Put` covering the captured heads and retains action provenance. If this changes no displayed fields, it does not manufacture a text-undo entry: undo cannot erase that causal acknowledgment or choose an implicit parent. A choice that changes fields has ordinary compensating undo. Merely displaying/recomputing a merge is not an undo-stack entry. A later edit starts from the displayed merged value with its exact descriptor as before-state. Keep the inspector available from history after the note changes again, provided its input evidence remains retained.

All recovery actions use normal admission, action grouping, local segment/parent barriers and plaintext projection obligations. The × remains enabled while admitted work persists. Display local-save/file-save status separately; retries only finish already admitted work and cannot silently repeat a recovery click against a newer Current. Reuse the existing per-item bounded attempt/re-presentation behavior where an operation needs I/O. No new modal recovery loop or provider-history completeness promise is introduced.

### Recently Deleted

Add a separate **Recently Deleted Notes** viewer window with read-only note previews and one **Restore** recovery action, not a redundant **Save as new note** control. The latter remains available in Note History and conflict resolution under their separate contracts. Reuse presentation components, not a mode that replaces the ordinary window's list/search/editor. Its entries come from logical Deletes and retained note values, including known remote deletions, not a scan of a filesystem Trash directory. In v1 the name is a convenience label: there is no 30-day expiration or automatic purge. Normal note search/list counts continue to exclude deleted entries.

Restore creates a fresh birth with `restoredFrom` identifying the source deletion/revision and a collision-adjusted output name; it never erases the old Delete/retirement or clobbers a current same-name file. The new note joins the shared live model on admission. Once that restoration and provenance reach their local segment barrier, remove the source entry from the default Recently Deleted listing, making recovery effectively a move back to ordinary notes. Do not wait for separate-file installation, provider upload or remote acknowledgment. Until then retain the source row's pending/failure status; double-clicks/background retries reuse the one admitted action. An explicit later historical copy is a new action. Restores initiated concurrently on two Macs may produce two preserved new notes; do not promise global exactly-once restoration or unify them solely by old UUID/body.

Derive source-row exclusion from complete locally durable restoration history as specified in [Protocol](Protocol.md#historical-recovery-and-deleted-note-history), not a persisted UI flag, local undo eligibility or continued existence of the restored note. Rebuild it after restart/index reconstruction and apply the same rule to validated, locally persisted remote restorations. If the fresh note is subsequently deleted, including by guarded Undo of Restore, show a new deletion entry for that birth's then-current recoverable history; do not resurface the original entry. Preserve the old deletion, prior branches and restoration link in history. No history erasure, same-name file deletion or unrelated conflict resolution follows from hiding a restored row.

An unexplained missing file stays in the existing external-deletion confirmation flow, not Recently Deleted. A conflict note from a delete/edit race is ordinarily editable, but its untouched automatic presence is recomputed from eligible source evidence; independent user actions remain protected. Restoring a deleted deterministic conflict note uses a fresh ordinary birth and leaves its original retirement intact. If the pre-delete history has multiple branches, show those choices rather than guessing a single old value.

### Shared-note windows and editor ownership

The separate [window UI architecture overview](Window-UI-Architecture.md) consolidates New Window and Recently Deleted behavior, ownership boundaries, current-source extraction points and the remaining UX decisions. The obligations below apply to that separation.

Separate window presentation state from `AppController`'s collection/session ownership before reusing its UI logic. Several ordinary windows share **one** live note store, local store/root session, admission gate, pending work, and per-note native/saved undo ownership. A window owns its query, selected item, live selection/layout/scroll and geometry, not another writable database or undo branch. Named collection actions retain their existing collection scope. This does not authorize asynchronous/debounced search or an unreviewed responder/table refactor; production keyboard/UI changes require the human sign-off and tests in `AGENTS.md`.

Retain the per-note remembered cursor location/length with last-update-wins behavior, including programmatic updates; another view's live selection remains independent. Treat this as remembered UI state, not a new body edit, compensation, or cross-machine ordering primitive. Read-only historical previews still own detached text and cannot mutate Current merely by selecting/copying a preview.

The smallest AppKit candidate is one TextKit-1 `NSTextStorage` per live note and a separate layout manager/container/text view for each attachment. Multiple containers on **one** layout manager implement flowing text and are not this arrangement. `NSLayoutManager replaceTextStorage:` transfers **all** layouts on the old storage; do not use it to switch just one window's note. Detach/rebind only that attachment's layout. Search highlighting uses per-layout temporary attributes, not authoritative content attributes. The [shared-window probes](Native-Undo-Experiments.md#shared-window-follow-up) verify selected concrete call sequences, not the actual LinkingEditor bridge or arbitrary view lifetime.

Implementation obligations:

- Admit a logical edit once through the note/model owner; observing views repaint/reindex without repeating the mutation, undo registration or pending capture. A saved capture may still batch several edits; no per-keystroke segment rule is introduced. Preserve immutable attributed snapshots and exact action/remaining-effect metadata through the existing local installer.
- Capture collection/root session, note birth/generation and view attachment generation before asynchronous preparation. Revalidate before admission or updating that attachment, including X→Y→X reuse. After admission, model-bound pending work survives detach/close; completion cannot retarget through `currentNote`, reopen a view, or clear a newer generation. Closing the final view is not closing the collection.
- Route Undo/Redo from any ordinary view to its captured note's shared owner. Admission failure must be checked **before** the manager consumes an entry. Switching to Y or closing A must not undo Y, discard X's remaining action coverage or require A to stay alive invisibly. Concrete deallocation/retention remains a measured integration gate; a successful detached undo alone is insufficient evidence.
- Follow the [platform-first input contract](../iCloud-Drive-Support-Spec.md#input-and-content-scope). Use standard AppKit handling for local focus changes, editor closure/note switching and another window's editing; do not impose custom cancellation or interpret synthetic peer input as normal focus transfer. Prefer deferring a remote body application to a safe input boundary, then revalidate and reconcile using existing merge/conflict policy. Composition alone does not create a conflict. Other notes and healthy local durability continue. The probe's separate snapshot/input-depth/refusal adapter is optional, not prescribed storage architecture; validate the actual editor through normal event delivery and real IMEs before adding such machinery. Internal storage notifications cannot manufacture completed user actions.

[`SharedNoteViewOwnershipSafety`](../tla/SharedNoteViewOwnershipSafety.tla) checks this ownership boundary with separate prepare/admit/observe/capture/install/complete/close/reopen/crash actions. Its composition scenario tests one separate-snapshot adapter under explicit assumptions, not the necessity of that adapter, normal input-context focus behavior, or a universal prohibition on recovery snapshots containing provisional text. Its invariants remain useful checks of the chosen fixture; they do not select production IME policy.

### Persistent meaningful-action undo

The [native undo investigation](Native-Undo-Experiments.md) records two-OS AppKit probes, worked saved-span bookkeeping, bounded models and the remaining concrete integration gates for phase 6c. Do not assume group-close notifications delimit every typing action, that `breakUndoCoalescing` closes an already open outer group, or that native range inverses rebase across untracked remote body replacement. The report's handoff strategy is a candidate, not an adopted relaxation of the rules below; particularly, coarser undo after a remote body update needs explicit acceptance.

Before considering that fallback, extend the existing probe with external changes registered through supported undoable editing paths. Compare localized edits and body replacement, separate versus coalesced groups, earlier/later typing, repeated Undo/Redo, and another view's command. Check exact text, native granularity, causal candidate selection and remaining-effect accounting, not just absence of exceptions. ## Quit, root closure, and storage transitions

One close operation owns these stages:

1. Finish or explicitly cancel external-editor handoffs; select lifecycle quiescing so no new mutation is admitted. Do not cancel already admitted changes.
2. Force capture and complete every required local operation plus dependency closure. Local failure keeps the app open with actionable recovery.
3. Persist/read back required Local State changes. Report unsaved private settings separately; an uncommitted association/key transition cannot be called successful. Derived materialization may lag durable history; its failure alone cannot fail a durable quit, but current rows must catch up before editable reopening.
4. For plaintext mode, settle or explicitly defer exact projection obligations under the established close policy. Their failure does not invalidate locally durable segment data. Retain restart-reconcilable intended outputs, local receipts, latest pending-file snapshots and frozen operation inputs; closing/switching is not abandonment. Report any failure to retain new pending evidence without deleting the previous retained copy. Never blindly replay physical deletion tokens or manual consent after restart.
5. Optionally wait for this close's exact provider objects using the existing user-facing upload-wait semantics. No provider-global “everything uploaded” inference. **Quit Without Waiting** leaves durable unpublished objects for next launch; cancel resumes admission if local health permits.
6. Drain/fence outstanding callbacks and presenters, release directory ownership last, then complete termination/root switch exactly once. `NSTerminateLater` is the single application termination handoff; avoid recursive quit requests or nested modal loops.

The local segment lane cannot be blocked behind step 5. A nonreturning provider accessor may require the existing fenced shutdown handling, not main-thread waiting. Capture operations already in flight before invalidation cannot retain live mutation authority after a root switch.

If the requested Save As includes switching to the copy, first verify it and use the ordinary explicit transition with a fresh private store, action origin, writer epoch and positive root/ownership checks; failure leaves the source active. Retain/settle any admitted source work before a switch rather than assuming a repository-only copy saved it. Equal collection identity means shared lineage, not permission to retarget or resume the old writer.

**Legacy migration, current-notes export, and key/profile conversion** instead capture coherent complete current values after recovery/external-edit settlement and create a fresh collection/key/local store/genesis/import/snapshot in an independent destination. Clearly disclose this current-state-only scope; it is not the full repository-copy command and may not silently replace it. Quiesce or invalidate/restart changed captures, verify all values/counts/required files and provision/read back optional independent Keychain storage before switching association. Source files/journals/history/credentials remain untouched until success and explicit later cleanup. Recovery of admitted unsaved text on local failure uses this explicitly scoped export or a repaired local barrier; a repository-only copy cannot clear that pending work. Epoch-4 export remains a genuine separate current-state legacy archive, not a live old-client mirror. Full-history key/profile transformation is a separate future protocol, not claimed by either byte copying or current-state conversion.

## Ordered delivery plan
